# IDO SPACE 付款与合同审批 Agent 执行标准

> **版本**：v1.2 | **编制日期**：2026-05-17
> **依据**：《付款审批 Agent 工作逻辑报告》《合同审批 Agent 工作逻辑报告》《付款审批 Agent 五项判断整合规则》及实际案例评审标注（万小骥）
> **相对 v1.1 的主要变更**：采纳五项判断整合规则，重构判断层级体系、证据管理机制、建议信心逻辑和建议卡模板结构

---

## 一、总则

### 1.1 适用范围

本标准规定 IDO SPACE 付款审批 Agent 与合同审批 Agent 在执行审批判断时必须遵循的**输出格式、判断准则、证据要求和表述规范**。所有审批建议卡在交付审批人之前，必须通过本标准的合规检查。

### 1.2 核心原则

| 原则 | 说明 |
|-|-|
| **判断可追溯** | 每个结论必须附带信息来源或标注「待确认」 |
| **量化优于定性** | 凡涉及金额大小、价格高低、风险等级，必须有阈值标准或参照基准 |
| **条件可关闭** | 「条件通过」的条件必须包含四要素：内容 + 责任人 + 截止时间 + 逾期处理 |
| **证据对应金额** | 附件描述必须逐项列出、对应金额、区分凭证类型、标注风险 |
| **区分过程与结果** | 复盘评估必须区分「过程产出」和「最终产出」 |
| **不自证其无** | 不能断言「不需要某物」，只能说「未发现要求」或「待确认」 |
| **五项判断不独立** | 五项判断不是五个互斥的信息分类，也不适合做简单加总评分。一个证据点经常同时影响多个判断 |
| **证据集中管理** | 同一证据点可以影响多个判断，但应先集中列出再由五项判断分别解释影响，不重复提出、不重复扣分 |
| **主判定优先** | 金额不符、节点不符、红线、基础材料缺失等核心问题，应先处理再展开五项判断 |

### 1.3 禁止表述清单

以下是审批 Agent 在建议卡中**禁止出现**的表述及其替代方案：

| 禁止表述 | 原因 | 替代表述 |
|-|-|-|
| 「不需要合同」 | 断言缺乏依据，Agent 无权自行决定 | 「截至审批时点，未查询到同类付款需合同的先例，**建议法务确认**」 |
| 「金额较小/较大」 | 无标准依据，纯主观 | 「按公司阈值标准属『中等』级别（¥15,900 ∈ 5-20万）」 |
| 「价格合理/不合理」 | 无参照基准 | 「价格较同供应商历史均价高 X%，较同类项目均价高 Y%」 |
| 「风险可控」 | 未说明如何控 | 「风险可通过以下条件控制：…（列具体条件）」 |
| 「提请关注」 | 不可执行 | 「条件通过——条件：… 责任人：… 截止：… 逾期：…」 |
| 「未产出结果」 | 不区分过程/最终产出 | 「过程产出 XX 已获得；最终产出 YY 因 ZZ 原因未达成」 |
| 「附件包含缴费单」 | 笼统无金额对应 | 「①缴费单A.pdf（对应 ¥X，正式通知）②截图B.jpg（对应 ¥Y，非正式凭证）」 |

## 二、共同基础：六原子认知框架

两个 Agent 共用六原子模型作为底层认知语言。六原子不是字段表，而是 AI 理解企业事件的认知结构。

| 原子 | 核心问题 | 付款中的作用 | 合同中的作用 |
|-|-|-|-|
| Facts | 发生了什么？ | 金额、合同、发票、供应商、付款节点、验收记录 | 合同主体、金额、期限、标的、交付物、付款条件、附件 |
| Relations | 和谁有关？ | 付款与合同、供应商、项目、预算、质量文件的关系 | 合同与客户、供应商、项目、管线、SO/PO、库存、部门的关系 |
| Rules | 受什么约束？ | 财务制度、合同条款、审批权限、预算规则、GMP/QA | 法律法规、公司制度、授权审批、合同模板、行业监管 |
| Logic | 为什么合理？ | 推导付/不付/延迟付的后果 | 推导权利义务对等性、付款交付匹配性、签/不签的后果 |
| State | 处于什么阶段？ | 项目阶段、合同状态、付款节点、预算/现金流状态 | 项目阶段、谈判状态、库存/产能/预算/资源状态 |
| Goal | 为了什么价值？ | 履约、保供应、保项目、控风险、提升 ROI | 收入、供应保障、项目推进、管线进展、战略合作 |

## 三、推荐工作结构

审批 Agent 应按照以下层级组织建议卡内容，确保主判定优先、证据集中、五项判断辅助。

| 层级 | 作用 | 输出 |
|-|-|-|
| 证据层 | 集中呈现合同、发票、验收、项目、历史履约、资金计划等关键事实，避免重复表达 | 关键证据 / 异常点 |
| 主判定 | 先识别当前单据最核心的审批问题，例如金额不符、节点不符、红线、基础材料缺失 | 主判定结论 |
| 五项判断 | 围绕审批人关心的五个决策问题，解释证据对各问题的影响 | 判断结论｜支撑等级｜关键描述 |
| 建议动作 | 根据主判定和五项判断，给出当前单据处理方式 | 通过 / 驳回 / 补材料 / 暂缓 / 条件通过 / 特批 |
| 建议信心 | 衡量 AI 对当前建议动作的把握，不是五项分数加总 | 高 / 中 / 低，或百分比 |

## 四、付款审批五项判断标准

### 4.0 五项判断的边界定义

五项判断不是五个互斥的信息分类，一个证据点经常同时影响多个判断。

**最简记忆**：真实性看「是不是真的」；合规性看「允不允许」；必要性看「不付会不会出事」；价值性看「付了值不值得」；承受性看「现金流扛不扛得住」。

| 判断项 | 主问题 | 不应混淆为 |
|-|-|-|
| 真实性 | 这笔付款对应的交易、金额、对象、交付是否真实成立？ | 不是判断是否值得，也不是判断企业是否付得起 |
| 合规性 | 这笔付款是否满足合同、制度、预算规则和审批规则？ | 不是判断现金流能不能承受 |
| 必要性 | 为什么现在要付？不付会不会影响合同履约、业务推进或组织义务？ | 不是判断价格是否划算 |
| 价值性 | 付了是否值得？这笔钱对应的投入产出是否成立？ | 不是判断现在是否必须付 |
| 承受性 | 企业当前资金安排是否支持本次付款？现金流是否扛得住？ | 不是判断预算是否允许 |

> **关键区分**：预算是否允许付款，归合规性；现金流是否扛得住，归承受性。承受性表述中不再使用「预算余额」作为判断口径。

---

### 4.1 真实性 — 交易、金额、对象和交付是否真实成立

**定义**：真实性是付款审批的事实基础，重点不是判断价值，而是确认付款对应的业务事实是否存在、是否一致、是否可核验。

**必查项**：
- [ ] 合同编号/名称、对方名称、金额与审批单一致
- [ ] 发票内容（OCR 提取）与合同和审批单匹配
- [ ] 收款方名称、账号与供应商主数据一致
- [ ] 附件中的验收/交付证明齐全
- [ ] 与历史付款记录做重复检查

**判断层级**：

| 层级 | 判断口径 | 典型表达 |
|-|-|-|
| F1 通过 | 合同、PO、发票、验收/交付证明、供应商账户、金额、项目等一致 | 真实性：通过｜合同、发票、验收记录和供应商账户一致，付款对象和金额可核验 |
| F2 基本通过 | 核心事实成立，但存在轻微材料缺口，不影响主判断 | 真实性：基本通过｜核心材料一致，但验收附件仍需补充归档 |
| F3 需确认 | 有合同或发票等基础材料，但关键事实链不完整 | 真实性：需确认｜已提供合同和发票，但缺少验收记录和供应商账户主数据 |
| F4 存疑 | 关键字段冲突，如金额、主体、账户、项目、发票不匹配 | 真实性：存疑｜发票金额与合同付款节点金额存在差异，需要申请人说明 |
| F5 未通过 | 缺少真实业务依据，或存在明显错误付款、重复付款、虚假交易风险 | 真实性：未通过｜发票供应商与合同供应商不一致，无法确认真实付款依据 |

**附件描述规范**（强制执行）：
- 每个附件必须独立列出：文件名、对应金额、凭证类型（正式/非正式）、风险评估
- 禁止笼统描述（如「附件包含缴费单」），必须精确到金额对应
- 若某笔金额缺乏正式凭证，必须标明该金额占总付款的百分比

**附件描述模板**：

| 附件 | 对应金额 | 凭证类型 | 风险 |
|-|-|-|-|
| ①文件名A.pdf | ¥X | 正式XX | 低/中/高——原因 |
| ②文件名B.jpg | ¥Y | 非正式截图 | 中——¥Y 占总额 Z%，缺正式凭证 |

### 4.2 合规性 — 合同、制度、预算规则和审批规则是否允许

**定义**：合规性关注「规则上能不能这么付」。**预算在这里作为规则存在**：是否有预算额度、是否超预算、预算科目是否匹配、是否需要预算调整或超预算特批，都属于合规性。

**必查项**：
- [ ] 审批链节点和审批人完整（由飞书审批流决定，Agent 无需自行判断权限）
- [ ] 合同付款条款（OCR 提取并对照）
- [ ] 预算归属正确、预算额度充足、预算科目匹配
- [ ] 付款类型与制度要求一致（预付/进度/验收/尾款）
- [ ] GMP/QA 合规（CGT 行业特殊要求）

**判断层级**：

| 层级 | 判断口径 | 典型表达 |
|-|-|-|
| R1 通过 | 付款节点、付款条件、审批权限、预算规则、制度要求、政策和监管规则均满足 | 合规性：通过｜已到合同付款节点，预算科目和审批层级均符合要求 |
| R2 存在例外 | 存在非标准情形，但可能通过补充审批、特批或说明解决 | 合规性：存在例外｜该付款超出项目预算余额，需补充预算调整或特批审批 |
| R3 规则冲突 | 当前付款条件未满足，或与合同、制度、审批规则明显冲突 | 合规性：规则冲突｜第三期尚未到付款节点，当前申请缺少提前付款依据 |
| R4 红线不通过 | 触碰不可豁免规则，如主体异常、黑名单、重大合规风险 | 合规性：未通过｜供应商账户异常且未提供合规确认，不建议审批 |
| R5 无法判断 | 缺少合同付款条款、审批制度、预算规则或授权矩阵 | 合规性：无法判断｜缺少合同付款条款和审批权限规则 |

**合同缺失的处理规范**：
- **禁止断言「不需要合同」**——Agent 无权自行决定某笔付款是否免于合同要求
- 若审批时无合同，必须执行以下步骤：
  1. 查询同供应商历史付款的合同覆盖率
  2. 查询同类费用（如同类 IIT 审查费）的合同先例
  3. 建议法务确认无合同付款的合规风险
  4. 在建议卡中标注「待确认」而非「不需要」

**合同存在但未走数字审批的处理规范**：
- 若付款审批单选了「有合同」但未关联合同审批实例，Agent 必须检查附件 PDF：
  1. **核验签章**：视觉分析确认是否有双方公章/合同专用章——双章齐全视为法律有效
  2. **核验内容**：提取合同金额、服务内容、付款条款，与付款审批单对照
  3. **分类处理**：
     - 双章齐全 + 内容一致 → **条件通过** + 要求法务确认合规豁免 + 合同台账补录 + 后续强制数字审批
     - 单章或无章 → **驳回补材料**，要求补走合同审批流程
     - 附件无合同 PDF → **驳回补材料**，要求上传合同
  4. **禁止**：仅凭附件 PDF 放行而不标注合同审批缺失——必须在条件中明确要求补充合规确认
- **理由**：线下双章合同法律有效，驳回重走审批的流程成本通常高于补充合规确认的收益。但合同条款/资质/金额未经内部审核是实质性缺口，不能免除条件追踪

### 4.3 必要性 — 为什么现在要付

**定义**：必要性关注付款的当前支付理由：如果现在不付，是否会影响合同履约、业务连续性、项目推进、法定义务或组织安排。

**必要性分层规则**：

| 层级 | 必要性来源 | 判断强度 | 典型表达 |
|-|-|-|-|
| N1 | 法定 / 监管 / 强制义务 | 很强 | 必要性：高｜该付款属于法定或监管义务，延迟可能导致处罚或资质风险 |
| N2 | 合同到期履约义务 | 很强 | 必要性：高｜该付款已到合同约定节点，公司存在按约付款义务 |
| N3 | 已发生业务事实 | 强 | 必要性：中高｜相关服务/交付已完成并经确认，付款用于结清已发生义务 |
| N4 | 业务连续性 / 紧急事项 | 强或中强 | 必要性：高｜若不支付，可能影响供应连续性、后续交付或关键项目节点 |
| N5 | 内部批准 / 计划内安排 | 中 | 必要性：中｜该付款对应已批准业务安排，但仍需结合价值性和承受性判断 |
| N6 | 仅申请人主张 | 弱 | 必要性：支撑不足｜当前仅有申请人说明，缺少合同、交付、审批或业务影响依据 |
| N7 | 无依据 | 不成立 | 必要性：无法判断 / 未成立｜缺少付款触发依据，建议补充材料 |

**按付款场景的必要性判断**：
- **有合同**：必要性优先看合同付款义务是否到期，并确认付款条件是否满足
- **超合同或提前付款**：必要性默认不成立，必须说明不提前付款会造成的业务影响
- **无合同**：必要性来自法定义务、已发生业务事实、内部批准、紧急事项或业务连续性
- **以上都没有**：必要性无法判断，应补充材料

---

### 4.4 价值性 — 付了是否值得

**定义**：价值性关注付款的投入产出逻辑：这笔钱支付后，企业换来的交付成果、业务结果、风险降低或长期价值，是否足以支撑付款金额和付款安排。

**价值性分层规则**：

| 层级 | 价值来源 | 判断强度 | 典型表达 |
|-|-|-|-|
| V1 | 直接支撑关键目标 / 避免重大损失 | 很强 | 价值性：高｜该付款直接支撑关键节点，避免的潜在损失显著高于付款金额 |
| V2 | 形成明确交付成果 | 强 | 价值性：较高｜付款对应明确交付物，成果可验收并可用于后续业务 |
| V3 | 保障供应 / 锁定资源 / 维持关键关系 | 强或中强 | 价值性：较高｜付款有助于锁定关键资源或维持关键合作关系，降低后续中断风险 |
| V4 | 正常业务闭环 / 常规履约价值 | 中 | 价值性：中｜该付款支持正常合同履约和业务闭环，但未体现额外增量价值 |
| V5 | 组织能力或长期价值 | 中或偏高 | 价值性：需说明｜付款可能形成长期能力，但需补充成果形态、复用场景和预期收益 |
| V6 | 价格 / 方案价值不清 | 弱 | 价值性：支撑不足｜缺少价格合理性、替代方案或投入产出说明 |
| V7 | 交付物 / 产出不清 | 很弱 | 价值性：低 / 无法判断｜未说明明确交付物、业务产出或可验收结果 |
| V8 | 明显不值得 | 不成立 | 价值性：不成立｜该付款无法形成明确业务价值，或与当前业务目标明显不匹配 |

**按付款性质的价值判断**：
- **后付款**：看本期成果是否完成、验收、可用
- **预付款**：看上一期成果是否支持继续投入，以及下一阶段目标是否清楚
- **提前付款**：看是否带来折扣、排产锁定、交付保障、避免延期等增量价值
- **无明确交付物、业务场景或价格依据**：价值性支撑不足

**量化维度**（必须包含，即使当前数据不足也要列出为缺口）：

| 维度 | 计算方法 | 当前是否可用 |
|-|-|-|
| 预算占比 | 本次付款金额 ÷ 项目总预算 × 100% | 需项目总预算（当前缺） |
| 横向比价 | 本次单价 vs 同类费用历史均价 | 需费用基准库（当前缺） |
| 延期损失 | 不付的预估损失 vs 本次付款金额 | 需业务负责人提供 |

**定价参照规则**：
- Agent 优先从历史付款中自动统计同供应商同类付款的均价作为参照
- 若价格偏离历史均价超过 30%，必须标注「价格偏离」并提示确认
- 禁止在无参照基准的情况下断言「价格合理」

---

### 4.5 承受性 — 现金流是否扛得住

**定义**：承受性用于判断企业当前资金安排是否支持本次付款。**为避免与合规性中的预算控制混淆，承受性表述中不再使用「预算余额」作为判断口径。**承受性只看资金计划与现金流：可用现金余额、本期支出计划、短期现金流预测、本次付款金额、付款优先级和安全现金线。

**承受性简化公式**：

> 付款后资金余量 = 可用现金余额 + 预计短期现金流入 - 本期支出计划 - 本次付款金额

判断重点是付款后资金余量是否高于安全现金线，以及是否影响更高优先级支出。

**判断层级**：

| 层级 | 承受状态 | 判断口径 | 典型表达 |
|-|-|-|-|
| C1 | 可承受 | 付款后资金余量仍高于安全现金线，不影响本期支出计划 | 承受性：可承受｜当前可用现金和短期现金流预测可覆盖本次付款及本期支出计划，付款后仍保留安全余量 |
| C2 | 基本可承受 | 付款后仍能覆盖本期支出计划，但资金余量明显下降 | 承受性：基本可承受｜本次付款后仍可覆盖本期支出计划，但资金安全余量下降，建议财务确认付款节奏 |
| C3 | 偏紧 | 付款后接近安全现金线，可能压缩其他重要付款安排 | 承受性：偏紧｜本次付款后资金余量接近安全现金线，可能压缩其他重要付款安排 |
| C4 | 不可承受 | 付款后低于安全现金线，或影响工资、税费、关键供应商、核心项目支出 | 承受性：不可承受｜本次付款后资金余量低于安全现金线，可能影响工资、税费、关键供应商或核心项目支出 |
| C5 | 无法判断 | 缺少可用现金余额、本期支出计划或现金流预测 | 承受性：无法判断｜缺少可用现金余额、本期支出计划和现金流预测 |

**金额大小的标准化**（禁止主观判断）：

| 级别 | 绝对值范围 | 典型业务含义 |
|-|-|-|
| 极小 | < ¥10,000 | 无需特别关注承受性 |
| 小 | ¥10,000 - ¥50,000 | 月度预算内通常可覆盖 |
| 中 | ¥50,000 - ¥200,000 | 需确认当月付款计划 |
| 大 | ¥200,000 - ¥500,000 | 需财务负责人确认 |
| 重大 | > ¥500,000 | 需升级管理层审批 |

> **补充规则**：相对值同时生效。若绝对值属「小」但占当月剩余预算 > 50%，自动升级为「中」级关注。

---

### 4.6 证据集中管理：避免重复提出和重复扣分

同一证据点可以影响多个判断，但应先集中列在「关键证据 / 异常点」中，再由五项判断分别解释影响，避免在卡片中反复写、在评分中重复扣。

**证据一因多果示例**：

| 证据点 | 可能影响 | 处理方式 |
|-|-|-|
| 付款金额超过当前合同节点应付金额 | 主要影响合规性，也影响必要性、价值性和承受性 | 作为主判定优先处理，不进入复杂评分 |
| 前一期交付结果不好 | 影响合规性、必要性、价值性和承受性 | 作为「分期履约检查」证据，不强行归入单项 |
| 缺少现金流预测 | 主要影响承受性 | 不影响预算合规性，但会降低当前支付建议的信心 |
| 无合同但已有验收事实 | 影响真实性、合规性和必要性 | 需找替代依据，并提示合规例外 |

## 五、合同审批七项判断标准

### 5.1 场景归因 — 合同从哪个真实业务场景来？

**定义**：在进入条款审查之前，必须先完成原始场景追踪，确定合同为哪个真实业务场景而存在。

**五级追踪体系**：

| 追踪层级 | 适用对象 | 归因路径 |
|-|-|-|
| 一级：主营业务 | CGT 主业务合同 | 合同 → 管线/研发/临床项目 → 批次/物料/服务/检测 → IND/注册节点 |
| 二级：业务交易 | 销售、采购类合同 | 合同 → SO/PO/采购申请 → 库存/交付/生产计划 |
| 三级：组织对象 | 支持运营类合同 | 合同 → 部门/成本中心 → 预算 → 组织目标 |
| 四级：一般运营 | 常规行政、基础服务 | 预算内、采购周期、历史价格基准、常规消耗 |
| 五级：无法追踪 | 无法关联任何对象 | **视为高风险，建议驳回补材料** |

---

### 5.2 真实性 — 交易背景和合同信息真实吗？

**必查项**：
- [ ] 签约主体名称、工商登记信息
- [ ] 对方主体资质（营业执照/经营资质）
- [ ] 签署人授权文件
- [ ] 交易背景说明（申请人填写）
- [ ] 报价单/技术协议与合同金额、标的匹配

---

### 5.3 合规性 — 能不能按规则签？

**必查项**：
- [ ] 法律红线检查（强制性规定 / 公序良俗 / 国家安全 / 公共利益 / 公平竞争 / 虚假交易 / 关联交易）
- [ ] 标准合同模板对照（法务提供模板库 → 知识库 RAG 检索）
- [ ] 授权审批（飞书审批流已配置）
- [ ] 行业监管要求（数据合规/出口管制/反商业贿赂）
- [ ] GMP/QA 文档要求

**红线触发规则**：

| 红线类别 | 触发条件 | 建议动作 |
|-|-|-|
| 强制性规定 | 违反法律、行政法规强制性规定 | **不通过** / 法务专项审查 |
| 公序良俗 | 违背公共秩序或善良风俗 | **不通过** / 法务专项审查 |
| 国家安全 | 影响政治、经济、军事、数据安全 | **升级合规审查** |
| 虚假交易 | 恶意串通、利益输送、虚假合同 | **不通过** |
| 关联交易 | 未披露关联关系或利益冲突 | **补材料** / 合规审查 |

---

### 5.4 风险性 — 权利义务和条款风险是否可控？

**重点审查项**：
- [ ] 技术协议完整内容
- [ ] 质量协议/验收标准
- [ ] IP 条款/保密条款
- [ ] 违约责任条款（是否对等、是否充分）
- [ ] 争议解决条款
- [ ] 交付与付款的匹配关系
- [ ] 赔偿责任上限

---

### 5.5 必要性 — 现在有没有必要签？

与付款必要性同源，额外增加：
- [ ] 不签是否影响关键项目节点（IND/临床/注册）
- [ ] 不签是否形成库存或供应风险
- [ ] 不签是否影响客户关系或组织目标

---

### 5.6 价值性 — 签了是否值得？

与付款价值性同源，额外增加：
- [ ] 合同对收入、供应保障、管线进展的直接贡献
- [ ] 价格与历史同类合同偏差
- [ ] 替代供应商或替代方案的可用性

---

### 5.7 履约性 — 企业能不能做到？

**定义**：判断企业当前是否有资源、产能、时间履行合同义务。

**必查项**：
- [ ] 项目资源排期 / 关键里程碑
- [ ] QA 审核周期
- [ ] 产能/交付能力状态
- [ ] 预算是否已预留

---

## 六、综合建议动作生成标准

### 6.1 建议动作类型

| 建议动作 | 适用条件 |
|-|-|
| **通过** | 所有判断项支撑充分或基本充分，无红线，风险低 |
| **条件通过** | 价值成立但存在可控风险，必须附加**可关闭的条件**（见 6.2） |
| **驳回补材料** | 缺少关键材料，无法形成可靠判断 |
| **暂缓** | 当前不适合，未来满足条件后可重新判断 |
| **不通过** | 事实不成立、触碰红线、价值明显不成立 |
| **升级特批** | 规则或目标冲突较大，需要人承担判断 |

### 6.2 「条件通过」的强制规范

> **「条件通过」不是「有问题但提醒一下」——它是「必须满足这些条件才能批准」。**

每项条件必须包含四要素：

| 要素 | 说明 | 示例（正确） | 示例（错误） |
|-|-|-|-|
| 条件内容 | 具体要完成什么 | 「补充伦理审查费正式收据并上传本审批单」 | 「完善附件」 |
| 责任人 | 指定到岗位或姓名 | 「市场运营中心/刘鸿飞」 | 「相关人员」 |
| 截止时间 | 具体天数或日期 | 「14 个工作日」 | 「尽快」 |
| 逾期处理 | 未完成怎么办 | 「逾期未补充则对应金额从项目预算冻结」 | （缺失） |

**条件通过模板**：

| # | 条件内容 | 责任人 | 截止时间 | 逾期处理 |
|-|-|-|-|-|
| 1 | 查询同类付款是否有合同先例；如无先例，法务出具合规意见 | 市场运营中心 + 法务 | 7 个工作日 | 逾期标记为合规例外，财务确认是否追溯 |
| 2 | 补充缺失金额对应的正式凭证 | 申请人 | 14 个工作日 | 逾期冻结对应预算 |

### 6.3 综合建议生成规则

综合建议不是取最低项，也不是五项机械加总，而是按以下逻辑判断：

1. **主判定优先**：先识别最核心问题（金额不符、节点不符、红线、基础材料缺失）
2. **是否存在红线？** → 是 → 不通过 / 驳回 / 合规专项审查
3. **多数项充分，少数需确认？** → 是 → 条件通过 / 补充确认后通过
4. **关键项缺失？** → 是 → 驳回补材料 / 暂缓
5. **信息不足但已发现明显风险？** → 是 → 不通过 / 升级确认

## 七、建议信心标准

### 7.1 建议信心不是五项分数加总

建议信心衡量 AI 对当前建议动作的把握，而不是五项判断的机械加总。信息不足时，如果建议是「补材料」且缺口明确，建议信心可以较高；如果建议是「通过」但关键项支撑不足，建议信心必须降低。

### 7.2 信心与场景的匹配逻辑

| 场景 | 建议动作 | 建议信心逻辑 |
|-|-|-|
| 合同节点、金额、验收、现金流均清楚 | 通过 | 高：资料足以支持通过 |
| 付款金额与当前合同节点不符，未提供提前付款依据 | 驳回重提 | 高：现有资料足以支持驳回 |
| 基础事实成立，但必要性/价值性/承受性支撑不足 | 补材料 / 暂缓 | 中高：对「需要补材料」有把握 |
| 业务紧急但规则冲突和资金压力都较大 | 升级特批 | 中低：需要人承担不确定性和价值判断 |

### 7.3 信心表达规范

建议信心使用「高 / 中 / 低」或百分比表达，并附信心来源说明。禁止仅输出一个数字而不解释信心依据。

## 九、复盘与后验规范

### 9.1 付款复盘必须区分

| 维度 | 问题 | 示例 |
|-|-|-|
| 过程产出 | 付款对应的直接交付/批准/节点是否获得？ | 「伦理答辩通过」「立项批准已出具」 |
| 最终产出 | 付款所服务的战略目标是否达成？ | 「临床数据未产出（因 818 号令全院暂停 NK）」 |
| 归因分析 | 最终产出未达成属于内部决策失误还是外部风险？ | 外部政策风险（818 号令），非付款决策可预见 |

### 9.2 项目终止/暂停的通用流程

当复盘发现项目已终止或暂停时，Agent 必须执行：

1. **逐项确认过程产出**：已支出的每笔费用，其对应的直接交付/批准/节点是否到位
2. **标注零产出项**：若某笔费用连过程产出都没有，标记为「零产出」并提示复盘
3. **系统化提示**：建议管理层对终止项目的已支出费用建立复盘机制

```
⚠️ 项目终止提示：
本项目的审查费过程产出已全部获得（立项批准、科学性审查通过、伦理答辩通过），
最终临床数据因外部政策暂停未产出。若其他终止项目存在连过程产出都为零的情况，
建议纳入风险复盘并确认是否需追责。
```

## 十、附件与证据标准

### 10.1 附件描述强制规范

禁止笼统表述，必须使用以下模板逐项列出：

```
附件清单：
| # | 文件名 | 对应金额 | 凭证类型 | 风险评估 |
|-|-|-|-|-|
| 1 | XX缴费单.pdf | ¥X | 正式XX通知 | 低 |
| 2 | 微信截图.jpg | ¥Y | 非正式截图 | 中——¥Y 占总额 Z%，缺正式凭证，若金额不符则缺少追索依据 |
```

### 10.2 凭证类型定义

| 类型 | 示例 | 可信度 |
|-|-|-|
| 正式合同/协议 | 双方签署的 PDF | 高 |
| 正式发票 | 税务系统电子发票 | 高 |
| 正式缴费通知 | 机构出具的标准格式通知单 | 高 |
| 正式收据 | 机构出具的收款凭证 | 高 |
| 银行回单 | 银行出具的转账记录 | 中高 |
| 验收/交付单 | 双方签署的交付确认 | 高 |
| 截图/微信记录 | 非正式沟通截图 | **低——仅作辅助参考，不可作为唯一凭证** |
| 单方说明 | 申请人单方面陈述 | **辅助——需交叉验证** |

### 10.3 凭证不一致时的处理

当不同附件对同一事项的描述不一致时：
1. 优先使用约束力更强的凭证（合同 > 发票 > 通知单 > 截图）
2. 不一致处必须在建议卡中标注
3. 若金额对应关系不清，**禁止自行推测**——标注为「待确认」并要求申请人澄清

## 十一、知识库与规则检索标准

### 11.1 规则来源优先级

审批 Agent 通过 RAG 检索公司知识库获取规则，不硬编码。检索优先级：

| 优先级 | 规则来源 | 示例 |
|-|-|-|
| 1 | 飞书审批流配置 | 审批权限（谁可以批多少金额）——已由飞书审批流决定，Agent 读取即可 |
| 2 | 公司制度文档（知识库） | 预算控制规则、报销制度、采购制度 |
| 3 | 法务模板库（知识库） | 各类合同标准模板 |
| 4 | 行业监管文档（知识库） | GMP/QA 合规、数据合规、出口管制 |
| 5 | 外部法规抓取（知识库） | 自动抓取 + 法务审核后入库，补充法务覆盖不全 |

### 11.2 规则检索失败的处理

当 RAG 检索无法找到匹配规则时：
- **禁止** 自行推断规则或说「不需要」
- **必须** 标注：「在知识库中未检索到相关规则，建议由 [对应部门] 确认」
- 将该条列入「待确认」清单

## 十二、Agent 边界与人工判断的交接标准

### 12.1 Agent 负责

- 事实核验和交叉比对
- 规则检索和合规对照
- 历史数据统计和基准比对（如均价）
- 风险识别和模式匹配
- 缺口清单生成
- 建议方案生成（基于规则和先例）

### 12.2 必须移交人工判断的情形

| 情形 | 移交对象 |
|-|-|
| 规则冲突且无明确例外处理机制 | 法务 / 财务 / 管理层 |
| 目标冲突（如保项目 vs 保现金流） | 管理层 |
| 高不确定性且业务紧急 | 管理层（升级特批） |
| 触碰合规红线 | 法务 / 合规 |
| 现金流极度紧张 | 财务负责人 |
| 价格严重偏离基准（>50%）且无合理解释 | 采购 / 财务 |

```
建议倾向：[AI 的推荐，附带理由]
```
