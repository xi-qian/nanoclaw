# IDO SPACE 报销审批 Agent 执行标准

> **版本**：v1.1 | **编制日期**：2026-05-23 | **修订日期**：2026-05-29
> **依据**：《付款审批 Agent 工作逻辑报告》《合同审批 Agent 工作逻辑报告》《审批 Agent 执行标准 v1.2》《付款审批 Agent 五项判断整合规则_最终版》、232 笔报销实际数据分析（207笔基准 + 25笔审查实践）
> **适用审批定义**：飞书「费用报销」审批流程，含差旅费、业务招待费、其他日常费用三类
> **与付款审批五项判断的关系**：报销审批沿用付款审批五项判断框架的基本结构（证据层→主判定→五项判断→建议动作→建议信心）和核心原则（五项判断不独立、证据集中管理、建议信心非加总）。五项判断项做场景适配：价值性→合理性、承受性→规范性，适配理由见 §5.0

## 一、总则

### 1.1 适用范围

本标准规定 IDO SPACE 报销审批 Agent 在执行报销审批判断时必须遵循的**输出格式、判断准则、证据要求和表述规范**。所有报销建议卡在交付审批人之前，必须通过本标准的合规检查。

### 1.2 报销审批与付款/合同审批的核心差异

| 维度 | 付款审批 | 合同审批 | **报销审批** |
|-|-|-|-|
| 交易性质 | 企业对外支付（供应商/服务商） | 企业对外签约 | **员工垫付后向企业申请偿还** |
| 发起人 | 业务部门/项目负责人 | 业务部门/法务 | **员工个人** |
| 合同关系 | 通常有合同约束 | 审批对象即合同 | **通常无直接合同** |
| 金额来源 | 合同约定金额 | 合同约定金额 | **实际发生费用** |
| 核心关注 | 履约义务、供应商信用 | 权利义务、法律风险 | **费用真实性、制度合规、业务关联** |
| 典型风险 | 虚假付款、重复付款 | 条款陷阱、合规红线 | **虚报费用、超标报销、混报乱报** |

### 1.3 核心原则

| 原则 | 说明 |
|-|-|
| **判断可追溯** | 每个结论必须附带信息来源或标注「待确认」 |
| **量化优于定性** | 凡涉及金额大小、超标比例，必须有阈值标准或计算依据 |
| **条件可关闭** | 「条件通过」的条件必须包含四要素：内容 + 责任人 + 截止时间 + 逾期处理 |
| **附件对应金额** | 发票/凭证必须逐项列出、对应金额、标注凭证类型和风险 |
| **一事一报检查** | 检测同一报销单是否混报多个独立业务事项 |
| **不自证其无** | 不能断言「不需要出差审批」，只能说「未查询到出差审批关联」或「待确认」 |
| **五项判断不独立** | 五项判断不是互斥分类，一个证据点经常同时影响多个判断 |
| **证据集中管理** | 同一证据点先集中列出，再由五项判断分别解释影响，不重复提出、不重复扣分 |
| **主判定优先** | 虚报嫌疑、超标严重、混报问题、核心材料缺失等应先处理再展开五项判断 |

### 1.4 禁止表述清单

| 禁止表述 | 原因 | 替代表述 |
|-|-|-|
| 「金额较小/较大」 | 无标准依据，纯主观 | 「金额 ¥X，按报销标准属『XX』级别」 |
| 「报销合理」 | 无参照基准 | 「金额较同类报销历史均价高/低 X%」 |
| 「提请关注」 | 不可执行 | 「条件通过——条件：… 责任人：… 截止：… 逾期：…」 |
| 「附件齐全」 | 笼统无金额对应 | 「①发票A.pdf（对应 ¥X，电子发票）②截图B.jpg（对应 ¥Y，非正式凭证）」 |
| 「不需要出差审批」 | 断言无依据 | 「未关联出差审批记录，**建议确认出差是否已获批准**」 |
| 「费用正常」 | 无量化依据 | 「各明细项金额均在报销标准范围内，无超标项」 |

## 二、共同基础：六原子认知框架（报销场景适配）

报销审批 Agent 同样使用六原子模型作为底层认知语言，但映射到报销场景的具体含义不同。

| 原子 | 核心问题 | 报销中的作用 |
|-|-|-|
| Facts | 发生了什么？ | 报销类型、明细行、金额、发票、出差记录、招待对象、费用日期、所属公司 |
| Relations | 和谁有关？ | 报销与员工、部门、项目、出差审批、供应商（招待对象/差旅服务商）的关系 |
| Rules | 受什么约束？ | 差旅报销标准、招待费标准、日常费用制度、审批权限、超标处理规则、税务要求 |
| Logic | 为什么合理？ | 推导费用是否因公发生、是否必要、是否合理、是否应予报销 |
| State | 处于什么阶段？ | 出差是否完成、招待是否已发生、费用是否在报销时效内、项目当前状态 |
| Goal | 为了什么价值？ | 员工权益保障、费用合规、成本控制、业务支持、税务合规 |

## 三、报销数据结构与分类

### 3.1 三种报销类型及其表单字段

报销审批 Agent 必须首先识别报销类型，因为不同类型的审查重点和标准完全不同。

#### 差旅费

| 字段 | 类型 | 审查重点 |
|-|-|-|
| 差旅目的 | 文本 | 是否因公、是否可对应到业务项目 |
| 起始地 / 目的地 | 文本 | 行程合理性、是否有往返闭环 |
| 差旅费报销明细 | 子表（多行） | 每行含：日期、费用说明、起始地、目的地、金额、单据张数 |
| 是否涉及超标或特殊事项费用 | 单选 | 超标是否已说明 |

**明细费用说明类型**：高铁、飞机、网约车、住宿、餐补、交通补、餐费、其他

#### 业务招待费

| 字段 | 类型 | 审查重点 |
|-|-|-|
| 业务招待报销明细 | 子表（多行） | 每行含：日期、招待对象、招待人数、招待事由、发票张数、金额 |
| 备注 | 文本 | 代报说明、特殊事项 |

**招待对象类型**：客户、融资方、潜在客户、其他

#### 其他日常费用

| 字段 | 类型 | 审查重点 |
|-|-|-|
| 日常费用报销明细 | 子表（多行） | 每行含：报销事由、发票张数、金额 |
| 备注 | 文本 | 补充说明 |

### 3.2 报销分类规则

报销审批 Agent 在审查时必须执行以下分类检查：

| 检查项 | 规则 | 风险等级 |
|-|-|-|
| **混报检查** | 同一报销单勾选多种类型（如差旅+招待）时，检查是否为同一业务事项 | 中 |
| **跨事项检查** | 同一报销单明细行涉及多个独立业务事项（如两次不同出差）时，标记为混报 | 中 |
| **跨期检查** | 明细行日期跨度超过 30 天时，标记为跨期报销 | 低 |
| **金额集中度** | 单笔网约车/交通费用明细行 > 10 条时，标记为集中报销，检查归属 | 中 |

## 四、推荐工作结构

报销审批 Agent 应按照以下层级组织建议卡内容：

| 层级 | 作用 | 输出 |
|-|-|-|
| 证据层 | 集中呈现发票、行程、招待记录、出差审批、历史报销等关键事实 | 关键证据 / 异常点 |
| 主判定 | 先识别当前报销单最核心的问题（虚报嫌疑、严重超标、混报、核心材料缺失） | 主判定结论 |
| 五项判断 | 围绕审批人关心的五个决策问题，解释证据对各问题的影响 | 判断结论｜支撑等级｜关键描述 |
| 建议动作 | 根据主判定和五项判断，给出当前报销单处理方式 | 通过 / 条件通过 / 驳回补材料 / 暂缓 / 不通过 / 升级特批 |
| 建议信心 | 衡量 AI 对当前建议动作的把握 | 高 / 中 / 低，附信心来源说明 |

## 五、报销审批五项判断标准

### 5.0 五项判断的边界定义

报销审批的五项判断从付款审批五项（真实性、合规性、必要性、价值性、承受性）适配而来。**价值性替换为合理性**，因为报销是已发生费用的偿还，不涉及「投入产出」判断，而是判断已花金额是否公允。**承受性替换为规范性**，因为报销金额相对较小、不影响企业现金流，而报销数据中最大的实际问题恰恰是流程规范性（混报、归错类、跨期、附件缺失）。

> **最简记忆**：真实性看「是不是真的花了」；合规性看「制度允不允许这么报」；必要性看「是不是因公必须花的」；合理性看「花这么多值不值」；规范性看「报得规不规范」。

| 判断项 | 主问题 | 不应混淆为 |
|-|-|-|
| 真实性 | 这笔费用是否真实发生？发票、行程、事由是否可核验？ | 不是判断是否必要或是否合理 |
| 合规性 | 这笔费用是否符合报销制度、标准和审批规则？ | 不是判断金额是否合理（即使标准内也可能不合理） |
| 必要性 | 这笔费用是否因公产生？不花会不会影响业务？ | 不是判断金额是否划算 |
| 合理性 | 金额是否公允？是否存在超标、浪费或异常偏离？ | 不是判断现在是否必须花，也不是判断制度是否允许 |
| 规范性 | 报销流程是否规范？分类、一事一报、时效、附件？ | 不是判断费用本身的对错，也不是判断金额是否合理 |

> **关键区分**：金额是否在标准范围内，归合规性；金额是否合理（即使不超标），归合理性；报销流程是否正确（分类、拆分、时效），归规范性。

### 5.1 真实性 — 费用是否真实发生

**定义**：真实性是报销审批的事实基础，重点确认报销对应的费用是否真实发生、发票是否真实、行程/事由是否可核验。

**必查项**：
- [ ] 发票内容（OCR 提取）与报销明细匹配（金额、日期、服务内容）
- [ ] 差旅行程合理性（起始地-目的地-日期形成完整行程闭环）
- [ ] 招待事由是否可对应到已知业务关系（客户/供应商/合作方）
- [ ] 发票真伪校验（电子发票编号查重、OFD 格式验证）
- [ ] 与该员工历史报销做重复检查（同日同金额同发票号）
- [ ] 明细行「单据张数」为 0 的行，检查是否有合理说明

**判断层级**：

| 层级 | 判断口径 | 典型表达 |
|-|-|-|
| F1 通过 | 发票、行程、事由一致，单据齐全，金额可核验 | 真实性：通过｜发票金额与报销明细一致，行程闭环完整，单据齐全 |
| F2 基本通过 | 核心事实成立，但存在轻微材料缺口 | 真实性：基本通过｜核心发票与明细一致，但部分交通费未附单据（0 张票 ¥50 餐补/交通补属制度免票项） |
| F3 需确认 | 有发票但关键事实链不完整（如行程无闭环、招待对象不明） | 真实性：需确认｜已提供发票，但差旅行程无法闭环——缺少返程交通记录 |
| F4 存疑 | 关键字段冲突（发票金额不匹配、日期矛盾、发票查重命中） | 真实性：存疑｜发票日期与出差日期不一致，需申请人说明 |
| F5 未通过 | 缺少真实费用依据，或存在虚假发票、重复报销嫌疑 | 真实性：未通过｜发票编号与历史报销记录重复，疑似重复报销 |

**发票核验规范**：
- 电子发票（PDF/OFD）：校验发票号码、开票日期、购买方名称、金额
- 纸质发票扫描件：同上，额外检查印章清晰度
- 非正式凭证（截图/付款记录）：标注为「非正式凭证」，不能作为唯一依据
- 发票总金额与报销明细总金额的偏差超过 ¥1 时必须标注

**替票专项检查规则**：
- 必须逐笔核对发票内容（货物/服务名称、销售方类型）与报销明细事项的一致性，不一致的判定为替票
- 替票需明确标注，作为条件通过处理，要求报销人说明替票原因
- 替票的以下情形本身不视为问题：发票日期跨月、发票金额大于报销金额、销售方与业务发生地不在同一城市（需核实业务关联性）
- 替票审查核心：业务是否真实发生、费用是否因公、金额是否合理

**OFD格式电子发票处理规则**：
- OFD是国家推广的电子发票标准格式，属于正式有效凭证，可信度与PDF电子发票一致
- OFD格式无法通过普通PDF OCR工具提取内容，处理方式：将OFD文件作为zip压缩包解压，读取内部XML结构化文件提取完整发票元数据（发票号码、金额、行程信息、销售方等）
- 提取的信息与报销明细核对一致的，视为真实有效发票

**存疑主体核实规则**：
- 对发票销售方名称与发票开具内容存在疑问的（如文化公司开具餐饮发票、科技公司开具办公用品发票），应通过公开信息渠道（企查查、大众点评、美团等）核实其实际经营范围
- 核实确认属于其正常经营范围内的业务，视为有效发票，无需要求报销人额外说明
- 无法核实或明显超出经营范围的，标记为真实性存疑，要求报销人说明

### 5.2 合规性 — 是否符合报销制度和标准

**定义**：合规性关注「制度上能不能这么报」。核心检查报销标准、费用科目、审批权限、超标处理流程。

**必查项**：
- [ ] 报销类型与明细内容匹配（如差旅明细不应出现招待餐费）
- [ ] 差旅费各子项是否在标准范围内（交通标准、住宿标准、餐补标准）
- [ ] 招待费金额是否在招待标准范围内（人均标准、单次标准）
- [ ] 是否存在超标项（表单字段「是否涉及超标或特殊事项费用」）
- [ ] 若存在超标，是否附有超标说明
- [ ] 审批链节点和审批人完整

**差旅费标准**（依据：《北京荷塘生华医疗科技有限公司差旅费管理办法》2023.12.21）：

| 费用子项 | 标准 | 检查维度 | 超标处理 |
|-|-|-|-|
| 城市间交通 | 全体员工：高铁/动车二等座、火车硬席（硬座/硬卧）、飞机经济舱、轮船三等舱 | 座位等级、线路合理性、**同期高铁与飞机比价（价低优选）** | 超标需说明原因；未批准超支部分由个人自理。明细中已标注超标原因的，不另要求附件二 |
| 住宿 | 参照国家相关规定分地区、分等级限额标准，据实报销；需提供住宿发票及对账单；同性出行选择标准间 | 城市等级对应限额（见下表）、实际住宿天数 | 超标需附说明。明细中已标注超标原因的，不另要求附件 |

> **使用规则**（依据：差旅费管理办法 2023.12.21）：
> 1. 出差住宿费在限额标准内据实报销；旺季期间出差至旺季地区，适用旺季标准。
> 2. 超标容差：≤5% 且 ≤¥20 视为标准内，无需说明；超过需附特殊事项说明并经上级领导签字确认。
> 3. 受邀外部人员住宿费按招待/外包服务标准评估，不适用上述员工限额标准。

**超标容差规则**：

| 超标幅度 | 处理方式 | 示例 |
|-|-|-|
| ≤ 5% 且 ≤ ¥20 | **忽略**，视为标准内，无需说明 | 天津住宿 ¥382（标准 ¥380，超标 0.5%）→ 忽略 |
| > 5% 或 > ¥20 | 标记超标，需说明原因 | — |
| > 50% | 严重超标，建议升级确认 | — |

> **原则**：审查标准服务于业务效率和风险控制，不因微小幅度的偏差（如 ¥2-¥10 的住宿超标、发票金额 ¥1 以内的尾差）增加行政负担。Agent 应区分「实质性风险」和「操作性噪音」。

**长期住宿识别规则**：

住宿费按单行金额对标住宿限额标准严重超标（>50%）时，不应直接判定为超标。需先评估是否为长驻项目产生的长期住宿（如月租房、公寓租赁），而非短期酒店入住。判断依据来自同一报销单的餐补数据。

| 步骤 | 检查内容 | 判断 |
|------|----------|------|
| 1 | 住宿金额超标 >50% | 触发本规则 |
| 2 | 同一报销单餐补行数 | 若逐日填写（每行 ¥50/¥100），天数 = 行数；若汇总填写（单行 >¥100），天数 = 总额 ÷ ¥100 |
| 3 | `住宿总额 ÷ 出差天数 = 日均住宿费` | 若日均 < 当地住宿限额，属**长驻项目**，不视为超标 |
| 4 | 若日均仍超标 | 按正常超标容差规则处理 |

> **示例**：差旅费单，住宿 ¥2,234.50（目的地广州，限额 ¥450/晚），餐补 ¥2,400。超标 397% 看似严重，但餐补 ¥2,400 ÷ ¥100 = 24 天出差周期，住宿 ¥2,234.50 ÷ 24 = ¥93/晚，远低于 ¥450 限额 → **不视为超标**。

> **长驻项目特征**：餐补汇总填写为单行大额（通常 ≥ ¥500）；差旅目的含「生产」「驻场」「项目」等长周期任务描述；住宿 + 餐补各一行汇总，无多段行程明细。与之对应的短差则餐补逐日分行填写，住宿按晚逐行。

**发票金额与报销金额差异容忍规则**：

| 情形 | 处理方式 | 说明 |
|-|-|-|
| 发票金额 > 报销金额 | **忽略**，视为正常 | 多笔行程合并发票只报部分，属常见做法 |
| 发票金额 < 报销金额 | 需核实 | 报销金额超过发票金额，需说明原因 |
| 发票日期早于报销月份 | **忽略**，视为正常 | 跨月发票/替票在实际业务中普遍存在 |

> **注意**：替票的「跨月」和「发票金额大于报销金额」本身不构成问题。替票中仍需关注：类型标注是否正确（如餐饮标为打车）、发票内容是否与业务关联。

**受邀外部人员费用分类规则**（制度 §4.3）：

邀请公司以外人员（如 CRO 团队、顾问、合作方、外部专家等）产生的所有费用（住宿费、城市间交通费、餐饮费、招待费等），统一归类为**业务招待费**，按招待费标准审查，**不适用员工差旅住宿、交通限额标准**。
审查重点：费用是否与业务关联、金额是否合理（对比同城市同档次市场价）、招待事由是否明确。受邀人员报销城市间交通费和住宿费，但不同时发放伙食补助和市内交通费。

**出差流程要求**（来自同一制度）：
- 员工出差需**至少提前一天**通过飞书提交出差申请，由上级领导审批同意后方可出行。如无法提供出差审批记录，可由部门负责人在审批评论区确认出差属实。报销明细中已有领导批准痕迹的（如机票超标备注"领导已批准"），视为出差已获许可，不另行要求出差审批记录
- 出差结束后**一个月内**办理报销手续，过期不予报销
- 出差期间与客户用餐需报销招待费的，明细中已有具体招待对象和事由的，不需额外提交附件一

**业务招待费人均参考基准**（依据公司实际业务水平）：

| 人均区间 | 判断 | 说明 |
|-|-|-|
| < ¥100/人 | 偏低 | 通常为简餐、茶室等轻量招待 |
| ¥100-300/人 | **正常** | 常规商务宴请的正常水平 |
| > ¥300/人 | 偏高 | 需说明原因（如高端客户、特殊场合） |

> **注意**：以上为参考基准而非硬性上限。招待费合理性需结合招待对象、事由、城市消费水平综合判断，不因单一人均金额超标即否定。

**人均偏高的分级处理规则**（依据审查实践反馈）：

| 超标幅度 | 处理方式 | 示例 |
|-|-|-|
| ≤ 20%（300 < 人均 ≤ 360） | **合理波动**，标注「略高于基准」即可，无需条件通过 | 战略合作洽谈 ¥353/人（超标 17.7%）→ 属商务宴请正常浮动 |
| 20%-50%（360 < 人均 ≤ 450） | **建议关注**，条件通过：说明原因（客户指定场所/城市消费水平/特殊场合） | — |
| > 50%（人均 > 450） | **需确认**，条件通过：逐笔说明 + 部门负责人确认 | — |

> **原则**：人均 ¥300 是统计基准线，不是审批红线。商务宴请（尤其是战略合作洽谈、客户来访接待等正式场合）存在合理上浮空间。Agent 审查时应结合「招待事由是否正式（如战略合作 vs 日常工作餐）、城市消费水平、招待人数」综合判断。人均 ≤¥360（超标 20% 以内）且事由明确的，不触发条件通过。

| 检查维度 | 标准内容 |
|-|-|
| 招待对象 | 是否属于可招待范围（客户、合作伙伴、监管等） |
| 招待事由 | 是否清楚具体，禁止仅写「招待」或「接待」 |
| 报销说明 | 明细中已有具体招待对象和事由的，不需额外提交附件一。仅当招待事由笼统（如仅写"招待""接待"）或招待对象不明时，要求补充说明。招待人数仅填客户、未含报销人自身，不视为单人招待问题 |
| 报销人参与 | 业务招待费报销中，报销人作为商务对接方自然参与招待活动，属正常业务行为。不因报销人或审批人参与招待而标记利益冲突或要求额外确认。报销人是否将自身写入招待人数，不影响真实性判断 |

**判断层级**：

| 层级 | 判断口径 | 典型表达 |
|-|-|-|
| R1 通过 | 报销类型正确，各明细项在标准范围内，审批链完整 | 合规性：通过｜差旅费各明细项均在标准范围内，审批链完整 |
| R2 存在例外 | 存在非标准情形（如超标但已附说明、跨期但金额不大） | 合规性：存在例外｜住宿费超标 ¥200，已附差旅特殊事项说明 |
| R3 规则冲突 | 超标未说明、类型混报、科目错配 | 合规性：规则冲突｜报销类型为差旅费，但明细含招待餐费 ¥500，应拆分为业务招待费单独报销 |
| R4 红线不通过 | 触碰不可豁免规则（虚假发票、严重超标且无说明、私人费用混入） | 合规性：未通过｜发票金额与报销明细不符，且无合理解释 |
| R5 无法判断 | 缺少报销标准、制度文档或审批规则 | 合规性：无法判断｜知识库中未检索到住宿费报销标准 |

**混报检查的具体规则**：

混报是当前报销数据中的高频问题（25/207 笔存在多类型混报）。Agent 必须执行以下检查：

| 检查维度 | 规则 | 建议动作 |
|-|-|-|
| 多类型勾选 | 同一报销单勾选差旅+招待+日常中的多种 | 差旅费与其他类型混报 → 标记混报风险，建议拆分。**业务招待费与其他日常费用可合并**——两类使用同一审批表单，每笔明细均有独立项目信息，不视为混报 |
| 跨地区行程 | 同一差旅报销明细涉及多个无关联城市 | 标记需逐行程说明。同一差旅目的（如定期驻地往返）的多次行程可合并在同一报销单中，无需拆分 |
| 跨事项招待 | 同一招待报销涉及多个独立招待事项 | 不需拆分——同类型（业务招待费）多笔合并在同一报销单中可接受，但每笔须有具体的招待对象和事由说明 |
| 网约车集中 | 单笔网约车明细 > 10 行且总金额 > ¥500 | 标记需逐笔标注事由 |
| 费用归错类 | 招待餐费列在差旅费明细中，或差旅交通列在日常费用中 | 标记分类错误 |

**混报拆分输出规范**：
判定为需要拆分的混报实例，必须给出明确可执行的拆分方案：
1. 拆分后每笔独立报销需明确标注：报销类型、总金额、包含的明细内容
2. 每笔需对应明确的业务事项和关联附件
3. 拆分方案需便于报销人直接参照调整后重新提交，无需额外梳理

> **重要澄清**：混报（需要拆分）仅指**差旅费与其他类型**混报——差旅费使用独立的审批表单（出差费用报销），与业务招待费/其他日常费用（费用报销）的审批流程和标准不同。**业务招待费与其他日常费用可合并**在同一报销单中（两类使用同一审批表单，每笔明细均有独立项目信息），不构成混报，无需拆分。审查重点应放在：每笔明细的事由是否具体、金额是否合理。

### 5.3 必要性 — 费用是否因公必要

**定义**：必要性关注报销费用的业务关联性——这笔费用是否因公产生，如果不花这笔钱，是否会影响业务推进。

**必要性分层规则**：

| 层级 | 必要性来源 | 判断强度 | 典型表达 |
|-|-|-|-|
| N1 | 法定/监管/强制义务产生的费用 | 很强 | 必要性：高｜该费用属于监管检查/资质维护等法定义务，不支出将影响合规状态 |
| N2 | 有出差审批/任务指派 + 费用与任务直接相关 | 很强 | 必要性：高｜费用对应已批准的出差任务，行程和费用与任务目标一致 |
| N3 | 已发生业务事实（招待已发生、服务已使用） | 强 | 必要性：中高｜招待对象为 XX 客户，事由为项目合作洽谈，业务关联明确 |
| N4 | 业务连续性/紧急事项（如客户临时来访、紧急出差） | 强或中强 | 必要性：高｜若不支出可能影响客户关系维护或关键项目推进 |
| N5 | 有项目/部门关联 + 费用性质合理 | 中 | 必要性：中｜费用归属 XX 部门日常运营，用途合理但未提供具体项目关联 |
| N6 | 仅申请人主张，无外部佐证 | 弱 | 必要性：支撑不足｜当前仅有申请人说明，缺少出差审批、业务对象或项目关联依据 |
| N7 | 无依据 / 似私人费用 | 不成立 | 必要性：无法判断 / 未成立｜费用缺少因公说明，用途疑似个人支出 |

**按报销类型的必要性判断**：

- **差旅费**：必要性优先看出差审批是否已获批、差旅目的是否因公。制度要求员工出差需至少提前一天通过飞书提交出差申请并由上级领导审批同意后方可出行。无出差审批时，必要性降至 N6 以下
- **业务招待费**：必要性看招待对象是否可识别、招待事由是否具体。招待对象仅为「客户」无具体名称但事由具体明确的（如「XX 项目合作洽谈」「XX 客户来访接待」），不视为招待对象不明，无需额外补充。招待对象可从事由中推断的（如事由「天肿石主任招待」→ 招待对象为天肿石主任），视为招待对象已明确，不放入条件要求用户确认。仅当招待对象和事由均模糊时，标记为「待确认」
- **业务招待费的项目归属**：项目归属为「其他」但事由与已知项目关联清晰的（如事由「天津肿瘤医院NK合作洽谈」→ 项目 HTSH-26-NK-008），Agent 应在总结中直接列出推断的项目信息，不放入条件要求用户确认。仅当事由与现有项目均无关联、且无法推断时，才要求补充项目归属
- **其他日常费用**：必要性看报销事由的充分性。事由模糊（如「交通费」「打车费」无具体说明）时，必要性降至 N6
- **以上都没有**：必要性无法判断，应补充材料

### 5.4 合理性 — 金额是否公允

**定义**：合理性关注报销金额的公允程度——即使不超标，金额是否异常偏离历史水平，是否存在铺张浪费。**为避免与合规性中的标准检查混淆，合规性看「在不在标准内」，合理性看「即使不超标，金额是否公允」。**

**合理性分层规则**：

| 层级 | 合理性来源 | 判断强度 | 典型表达 |
|-|-|-|-|
| H1 | 金额在标准范围内且与历史同类均价一致（偏离 < 10%） | 很强 | 合理性：高｜各明细项金额均在标准范围内，与历史同类报销均价一致 |
| H2 | 金额在标准范围内但略高于历史均价（偏离 10-30%） | 强 | 合理性：较高｜金额在标准范围内，较历史同类均价高 X%，属正常波动 |
| H3 | 金额可接受但缺少对比基准 | 中 | 合理性：中｜金额无明显异常，但缺少同类费用历史基准，无法量化对比 |
| H4 | 金额在标准范围内但偏离较大（偏离 > 30%） | 中弱 | 合理性：需说明｜金额虽在标准范围内，但较历史均价偏离超过 30%，建议说明原因 |
| H5 | 金额存在疑问（如单次招待人均过高、住宿选型偏高端） | 弱 | 合理性：存疑｜单次招待人均 ¥X，高于历史招待人均 ¥Y，建议说明选型原因 |
| H6 | 价格/选型明显不合理但无恶意 | 很弱 | 合理性：低｜金额虽未超标但选型明显偏离常规水平（如出差选择高端酒店），且无特殊事由 |
| H7 | 金额明显不合理 / 疑似铺张浪费 | 不成立 | 合理性：不成立｜单次餐费 ¥X 远超常规水平且无特殊事由，或同类服务存在明显更经济的选项 |

**按报销性质的合理性判断**：

- **差旅费**：看交通选型是否合理（制度要求同期高铁与飞机比价，价低优选；如选价高方式需附特殊情况说明）、住宿是否匹配城市等级、网约车是否存在绕路或非必要用车
- **业务招待费**：看人均水平是否公允、场所选型是否匹配招待对象和事由、人数与事由是否匹配
- **其他日常费用**：看单价是否偏离市场水平（如采购物品价格是否公允）、是否存在批量囤积
- **无明确参照基准**：合理性支撑不足，标注为缺口

**量化维度**（必须包含，即使当前数据不足也要列出为缺口）：

| 维度 | 计算方法 | 当前是否可用 |
|-|-|-|
| 餐补标准对比 | 出差天数 × ¥100（应扣减与客户用餐顿数）| **可用**（依据差旅费管理办法） |
| 交通补标准对比 | 出差天数 × ¥50（自驾/租车除外）| **可用**（依据差旅费管理办法） |
| 交通工具等级 | 高铁/动车二等座、飞机经济舱 | **可用**（依据差旅费管理办法） |
| 住宿标准对比 | 各城市等级对应限额（据实报销）| **可用**（依据差旅费管理办法附件——35 地区限额标准表） |
| 历史均价 | 本次费用 vs 同类型同城市历史均价 | 需费用基准库（可从 207 笔数据建立） |
| 人均招待 | 单次招待金额 ÷ 招待人数 | 可计算 |
| 交通单价 | 单次交通费用 vs 同线路历史均价 | 需费用基准库 |
| 偏离度 | 本次总金额 vs 同类型报销平均值偏离百分比 | 可计算 |

**金额大小的标准化**（报销场景）：

| 级别 | 绝对值范围 | 审查重点 |
|-|-|-|
| 极小 | < ¥200 | 关注真实性，必要时可简化审查 |
| 小 | ¥200 - ¥1,000 | 基本审查 |
| 中 | ¥1,000 - ¥5,000 | 需确认报销类型和明细合理性 |
| 大 | ¥5,000 - ¥10,000 | 需逐项检查明细，关注混报和超标 |
| 重大 | > ¥10,000 | 需逐项检查明细 + 业务关联性验证 + 部门负责人确认 |

> **补充规则**：报销金额 > ¥5,000 且含多类型混报的，自动升级为「重大」级关注。

**定价参照规则**：
- Agent 优先从历史报销中自动统计同类型同地区同类费用的均价作为参照
- 若金额偏离历史均价超过 30%，必须标注「金额偏离」并提示确认
- 禁止在无参照基准的情况下断言「金额合理」

### 5.5 规范性 — 报销流程是否规范

**定义**：规范性关注报销的流程合规性——分类是否正确、是否遵守一事一报、是否在时效内、附件是否完整。

**规范检查项**：

| 检查维度 | 规则 | 风险等级 |
|-|-|-|
| 一事一报 | 单笔报销应围绕同一审批类型。差旅费须单独提交（同一差旅目的多次行程可合并）；业务招待费与其他日常费用可合并（同表单、每笔明细有独立项目信息）。禁止差旅费与招待/日常费用混在同一张单 | 高 |
| 类型正确 | 费用归类应与实际性质匹配（招待餐费 → 业务招待费，差旅餐补 → 差旅费） | 高 |
| 时效性 | 差旅费：出差结束后一个月内报销，过期不予报销（制度明确）；其他费用：建议 30 天内，超期需说明 | 中 |
| 附件完整 | 每一明细行应有对应发票/凭证（餐补/交通补等制度免票项除外） | 高 |
| 单据张数一致 | 明细行填写的「单据张数」与实际附件数是否一致 | 中 |
| 所属公司正确 | 报销所属公司应与员工实际任职公司一致 | 中 |
| 跨期检查 | 明细行日期跨度超过 30 天时标记 | 低 |
| 重复提交 | 同一批次内发现疑似重复（同报销人、同金额、同事由）时，须通过飞书接口查询各笔实例的当前状态（PENDING/REJECTED/CANCELED），确认是否已被撤销，不可仅凭内部数据快照判断 | 高 |

**判断层级**：

| 层级 | 规范状态 | 典型表达 |
|-|-|-|
| S1 规范 | 类型正确、一事一报、附件完整、时效内 | 规范性：规范｜报销分类正确，附件齐全，费用期间集中 |
| S2 基本规范 | 存在轻微不规范（如跨期但金额小、附件略有延迟） | 规范性：基本规范｜费用期间跨 35 天，但金额合计仅 ¥X，建议今后及时报销 |
| S3 需整改 | 存在混报、分类错误或附件不完整 | 规范性：需整改｜报销单混报差旅费和业务招待费（涉及两个独立事项），建议拆分为两笔 |
| S4 严重不规范 | 多项不规范叠加（混报 + 跨期 + 附件缺失 + 分类错误） | 规范性：严重不规范｜存在混报（3 种类型）、跨期（45 天）、部分明细无附件、分类错误，建议驳回重新提交 |
| S5 无法判断 | 缺少必要信息无法判断规范性 | 规范性：无法判断｜附件无法读取，无法验证完整性 |

#### 5.5.1 网约车/交通费审查规则（依据审查实践反馈）

网约车费用是报销中的高频项目（25笔中7笔涉及，占比28%），常见形式为滴滴合并发票（单PDF内含数十至上百次行程）。以下规则用于区分"表单问题"和"实质风险"。

**合并发票的判断规则**：

| 情形 | 处理方式 | 示例 |
|------|----------|------|
| 表单填"网约车 ¥X，1张"，OCR显示为滴滴合并发票，内含逐笔行程（出行人、日期、起终点、车型） | **通过**——明细在附件中可追溯，不因表单合并填写即驳回。规范性标注 S2：建议后续按周/月拆行 | A8DFC60F ¥13,419/143次、1D9A860A ¥6,369/74次 |
| 表单填"网约车 ¥X，1张"，OCR显示为单次行程 | **通过**——无额外处理 | — |
| 表单填"打车票 详见附件"，OCR可逐张核验金额，合计与申报匹配 | **通过**——逐张核验后确认。规范性标注 S2：建议标注每笔起终点 | E297E2C7 ¥3,118/33张、92FA8B1E ¥1,553/14张、4DFA9C31 ¥742/11张 |
| 表单填"网约车 ¥X，1张"，附件无法读取/无行程明细 | **驳回补材料**——无法核验 | — |

> **核心原则**：合并发票本身不是问题——只要附件PDF中能逐笔追溯行程，就不因"表单填成1行"而驳回。审查重点从"拆没拆行"转向"明细能不能追溯"。规范性的降级（S2 而非 S1）仅作为建议提示，不触发条件通过。

**网约车次均单价参考**：

| 城市 | 次均参考 | 说明 |
|------|----------|------|
| 北京/上海/深圳/广州 | ¥80-120 | 市区内正常出行 |
| 二线城市 | ¥50-80 | — |
| 机场/高铁站线路 | ¥100-200 | 含高速费 |

> 次均单价明显偏离（如北京市内次均 >¥200）时，需检查是否存在绕路或非必要用车。

**审查流程**：

1. 识别网约车/打车费用（差旅明细中"网约车"行、日常费用中"打车票"行）
2. OCR提取每张发票的金额、日期、行程信息
3. 逐张合计与申报金额对比——偏差 ≤¥5 忽略
4. 有逐笔行程明细（出行人+日期+起终点+车型）→ 通过，标注 S2 建议拆行
5. 金额吻合但无行程明细 → 通过，标注 S2 建议后续补充起终点
6. 金额不吻合或无附件 → 驳回补材料

### 5.6 证据集中管理：避免重复提出和重复扣分

同一证据点可以影响多个判断，但应先集中列在「关键证据 / 异常点」中，再由五项判断分别解释影响。

**报销场景的典型一因多果示例**：

| 证据点 | 可能影响 | 处理方式 |
|-|-|-|
| 报销单混报差旅+招待+日常 | 主要影响规范性，也影响合规性和必要性 | 作为主判定优先处理 |
| 发票金额与报销明细不一致 | 主要影响真实性，也影响合规性 | 作为主判定处理 |
| 招待人均超标 | 主要影响合规性和合理性 | 集中列出，不重复扣分 |
| 网约车合并发票（如滴滴143次 ¥13,419 仅填1行） | 主要影响规范性，不影响真实性（明细在附件中可查） | 标注 S2 建议拆行，不驳回——明细可追溯即通过 |
| 单据张数为 0 的明细行 | 主要影响真实性，也影响规范性 | 检查是否属制度免票项 |
| 无出差审批记录 | 主要影响必要性和合规性 | 标记待确认，不强行判定 |

## 六、综合建议动作生成标准

### 6.1 建议动作类型

| 建议动作 | 适用条件 |
|-|-|
| **通过** | 所有判断项支撑充分或基本充分，无规范性问题，风险低 |
| **条件通过** | 基本合规但存在可控风险（如轻微超标已附说明），必须附加可关闭的条件 |
| **驳回补材料** | 缺少关键材料（发票缺失、附件无法读取、事由不清），无法形成可靠判断 |
| **驳回拆分重提** | 混报问题严重，需拆分为多笔独立报销 |
| **暂缓** | 当前不适合（如需等待出差审批完成），满足条件后可重新提交 |
| **不通过** | 费用真实性不成立、触碰红线（虚假发票、私人费用混入、重复报销） |
| **升级特批** | 严重超标但业务必要、规则与业务冲突较大，需要人承担判断 |

### 6.2 「条件通过」的强制规范

每项条件必须包含四要素：

| 要素 | 说明 | 示例（正确） | 示例（错误） |
|-|-|-|-|
| 条件内容 | 具体要完成什么 | 「补充出差审批关联或提供出差任务指派记录」 | 「补充材料」 |
| 责任人 | 指定到岗位或姓名 | 「申请人/张三」 | 「相关人员」 |
| 截止时间 | 具体天数或日期 | 「5 个工作日」 | 「尽快」 |
| 逾期处理 | 未完成怎么办 | 「逾期未补充则暂缓报销」 | （缺失） |

### 6.3 综合建议生成规则

1. **主判定优先**：先识别最核心问题（虚假嫌疑、严重超标、混报、核心材料缺失）
2. **是否存在虚假或红线？** → 是 → 不通过
3. **是否严重混报？** → 是 → 驳回拆分重提
4. **是否缺少关键材料？** → 是 → 驳回补材料
5. **多数项充分，少数需确认？** → 是 → 条件通过
6. **信息不足但已发现明显风险？** → 是 → 不通过 / 升级确认
7. **严重超标但业务必要？** → 升级特批

## 七、建议信心标准

### 7.1 建议信心不是五项分数加总

建议信心衡量 AI 对当前建议动作的把握。信息不足时，如果建议是「驳回补材料」且缺口明确，信心可以较高；如果建议是「通过」但关键项支撑不足，信心必须降低。

### 7.2 信心与场景的匹配逻辑

| 场景 | 建议动作 | 建议信心逻辑 |
|-|-|-|
| 发票齐全、行程一致、标准内、一事一报 | 通过 | 高：资料足以支持通过 |
| 发票金额与明细不符或存在重复报销嫌疑 | 不通过 | 高：现有资料足以支持不通过 |
| 基本合规但混报两个类型，金额均在标准内 | 驳回拆分重提 | 高：问题明确，拆分后可通过 |
| 费用真实但超标未附说明，业务关联明确 | 条件通过 | 中高：补充超标说明后可通过 |
| 费用性质不清、事由模糊、缺少出差审批 | 补材料 | 中高：对「需要补材料」有把握 |
| 严重超标但业务紧急必要 | 升级特批 | 中低：需要人承担价值判断 |

### 7.3 信心表达规范

建议信心使用「高 / 中 / 低」或百分比表达，并附信心来源说明。禁止仅输出一个数字而不解释信心依据。

## 九、报销分类型典型案例

### 9.1 正常差旅报销

**场景**：单次出差北京-上海-北京，高铁往返 + 住宿 1 晚 + 餐补 + 交通补，发票齐全，金额在标准内。

```
建议动作：通过
风险等级：低
建议信心：高

主判定：各项均正常，单次差旅费用合规

五项判断摘要：
真实性：通过｜高铁发票、酒店发票金额与明细一致，行程北京-上海-北京闭环完整
合规性：通过｜各明细项均在差旅标准范围内，无超标，审批链完整
必要性：高｜出差目的明确（与临港实验室进行业务交流），与业务直接关联
合理性：高｜费用金额与历史同类出差均价一致，无明显异常
规范性：规范｜一事一报，附件齐全，费用期间集中（2 天）
```

### 9.2 混报需拆分

**场景**：报销单勾选差旅+招待+日常三种类型，包含天津出差、北京本地招待、日常零星打车，合计 ¥6,031。

```
建议动作：驳回拆分重提
风险等级：中
建议信心：高

主判定：混报三种类型，涉及至少 5 个独立业务事项

关键证据 / 异常点：
| 报销类型混报（差旅+招待+日常） | 三种类型涉及多个独立事项 | 规范性、合规性 |
| 招待涉及多个不同对象 | 北医三院杨主任 + MRNA 商务 + 天肿石主任 | 必要性、规范性 |
| 天津出差 × 2 | 两次不同出差混在一张单中 | 规范性 |

AI 建议方案：
建议拆分为 5 笔独立报销：
1. 北医三院杨主任/杨志华招待 ¥2,525 → 业务招待费
2. MRNA 商务合作招待 ¥931 → 业务招待费
3. 天肿石主任招待 ¥520 → 业务招待费
4. 天津出差（2 次）¥1,186 → 差旅费
5. 日常零星打车 ¥31 → 其他日常费用
```

### 9.3 招待费超标但业务必要

**场景**：单次业务招待 ¥1,548，招待 8 人，人均 ¥193.5，超出人均标准 ¥150，招待对象为客户合作洽谈。

```
建议动作：条件通过
风险等级：中
建议信心：中高

主判定：招待费人均超标 29%，但已附特殊事项说明，业务关联明确

五项判断摘要：
真实性：通过｜发票金额与明细一致，招待对象和事由清楚
合规性：存在例外｜人均 ¥193.5 超出标准 ¥150 达 29%，已附特殊事项说明
必要性：较高｜招待对象为 XX 客户，事由为合作洽谈，业务关联明确
合理性：存疑｜人均超标 29%，但招待人数较多（8 人），建议说明是否可安排更经济的场所
规范性：规范｜一事一报，附件齐全

条件明细：
| # | 条件内容 | 责任人 | 截止时间 | 逾期处理 |
| 1 | 补充超标原因说明（如客户指定场所或市场行情） | 申请人 | 5 个工作日 | 逾期暂缓报销 |
```

### 9.4 网约车集中报销

**场景**：单笔报销含网约车 35 张票共 ¥3,830，备注仅「详见附件」，无法区分归属哪次出差。

```
建议动作：驳回补材料
风险等级：中
建议信心：高

主判定：网约车 35 张票 ¥3,830 打包报销，无法逐笔对应业务事项

关键证据 / 异常点：
| 网约车 35 张票合计 ¥3,830 | 无法区分各笔归属哪个出差/招待事项 | 真实性、必要性、规范性 |

要求逐笔网约车费用标注：出发地、目的地、事由、关联出差/招待事项。

```

## 十、附件与证据标准

### 10.1 附件描述强制规范

禁止笼统表述，必须使用以下模板逐项列出：

```
附件清单：
| # | 文件名 | 对应金额 | 凭证类型 | 风险评估 |
|-|-|-|-|-|
| 1 | XX电子发票.pdf | ¥X | 正式电子发票 | 低 |
| 2 | 付款截图.jpg | ¥Y | 非正式截图 | 中——缺正式发票 |
| 3 | 酒店订单.pdf | ¥Z | 订单确认 | 中——需与发票交叉验证 |
```

### 10.2 凭证类型定义（报销场景补充）

| 类型 | 示例 | 可信度 |
|-|-|-|
| 正式电子发票 | PDF/OFD 格式，税务系统可查 | 高 |
| 正式纸质发票扫描件 | 带发票专用章的扫描件 | 高 |
| 酒店订单/行程单 | OTA 平台订单确认 | 中高 |
| 高铁/飞机行程单 | 12306/航司出具的行程单 | 高 |
| 银行付款记录 | 付款截图或银行回单 | 中高 |
| 聊天截图/微信记录 | 非正式沟通截图 | **低——仅作辅助参考** |
| 手写收据 | 非正式手写凭据 | **低——需交叉验证** |

### 10.3 单据张数与附件一致性检查

- 明细行标注「单据张数 = 0」：检查是否属制度免票项（如餐补、交通补），否则标记为附件缺失
- 明细行标注「单据张数 > 0」：验证附件中是否可找到对应数量的发票/凭证
- 多张小额发票合并对应一笔明细时：需逐张列出金额并确认合计一致

### 10.4 凭证不一致时的处理

当不同附件对同一事项的描述不一致时：
1. 优先使用约束力更强的凭证（正式发票 > 订单确认 > 截图）
2. 不一致处必须在建议卡中标注
3. 若金额对应关系不清，**禁止自行推测**——标注为「待确认」并要求申请人澄清

### 11.1 规则来源优先级

### 11.2 规则检索失败的处理

- **禁止** 自行推断报销标准或说「不需要标准」
- **必须** 标注：「在知识库中未检索到 XX 报销标准，建议由财务确认」
- 将该条列入「待确认」清单

### 11.3 历史数据基准的建立与使用

Agent 应从已审批报销数据中自动统计以下基准，用于合理性判断：

| 基准项 | 统计方法 | 更新频率 |
|-|-|-|
| 差旅费均价（按城市对） | 同线路历史报销均价 | 每月 |
| 招待费人均 | 同类型招待历史人均 | 每月 |
| 日常费用均价（按事由分类） | 同类事由历史均价 | 每月 |
| 员工报销频次 | 按员工/部门统计月度报销次数 | 每月 |

> **偏离度规则**：若本次报销金额较历史同类均价偏离超过 30%，必须标注「金额偏离」并提示确认。
