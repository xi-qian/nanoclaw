## 一、合同模版与内容审查标准

> 表单字段为「**合同模版**」（`radioV2`），选项为 **有 / 无**（口语中「是/否」分别对应「有/无」）。
> 审查对象：附件 OCR 文本（`attachments_ocr_text`）或合同 PDF 正文。

### 1.1 标准模板库

模板文件位于本 skill 同目录 `Contract_Templates/`：

| 模板文件 | 适用场景 | 章节结构 |
|---------|---------|---------|
| `买卖合同模版.docx` | 采购类买卖合同（物料/设备/服务等实物或服务采购） | 十条标准章节 + 签字盖章页（见 §1.2） |

**新增模板时**：将 `.docx` 放入 `Contract_Templates/` 并更新上表；审查前用 `file-reader` 或解压 `word/document.xml` 读取模板正文作为比对基准。

### 1.2 标准模板章节结构（`买卖合同模版.docx`）

Agent 审查「合同模版 = 有」时，合同正文须与匹配模板保持**章节结构一致**，关键条款不得缺失或实质性改写：

| 章节 | 必备要点 |
|------|---------|
| 首部 | 买方/卖方法人名称、联系人、联系地址、联系电话、电子邮箱 |
| 一、标的 | 产品/服务明细表（名称、规格、数量、单价、总价） |
| 二、准确订货 | 卖方核对责任；缺货处理选项（三选一） |
| 三、交货时间、地点 | 交货期限、运输至买方指定地点、逾期违约金 |
| 四、付款 | 付款方式（预付/收货付/账期等）、卖方收款账户（账户名、税号、开户行、账号） |
| 五、发票 | 税率（模板默认 6% 增值税专用发票）、买方开票信息（账户名、税号、地址电话、开户行账号） |
| 六、质量保证 | 技术指标一致、低温运输、质量异议与退换货、**买方退货权**（见 §1.4）、非质量破损异议时限 |
| 七、不可抗力 | 定义、通知义务、免责 |
| 八、争议解决 | 协商不成向**买方所在地**有管辖权法院起诉 |
| 九、通知送达 | 书面通知、送达地址与联系人、变更提前告知 |
| 十、其他 | 意思表示真实、附件效力、不得单方变更解除、年度合同关系、份数及生效条件 |
| 签署页 | 双方盖章、法人或代理人签字、签署日期 |

### 1.3 合同模版 = 有：标准模板一致性审查

**触发**：`contract_template_text` = 有（或表单「合同模版」选「有」）。

**审查步骤**：

```
1. 根据 contract_type_text 选择 Contract_Templates/ 中最匹配的模板
   └ 采购类 → 买卖合同模版.docx
2. 读取模板正文 + 合同附件 OCR 文本
3. 结构比对：十条章节 + 签署页是否齐全
4. 关键条款比对：见下表「模板关键条款指纹」
5. 管理会计要素比对：见 §1.5（与表单/API 字段交叉验证）
6. 输出一致性结论：一致 / 部分偏离 / 严重偏离
```

**模板关键条款指纹**（偏离须标注并说明影响）：

| 条款 | 标准模板表述要点 | 偏离判定 |
|------|----------------|---------|
| 买方退货权（质量保证 §5） | 「买方有权将其**未拆封且质量合格**的合同标的物退还卖方……同等条件下**优先**从卖方处继续订货」 | 缺失或删除买方退货权 → **合规性规则冲突**；实质性限缩退货条件 → 条件通过 |
| 质量异议时限 | 收货后 **30 个工作日**内提出 | 短于 30 日 → 条件通过 |
| 逾期交货违约金 | 按日 **千分之五** | 显著低于或缺失 → 条件通过 |
| 争议解决 | **买方所在地**法院管辖 | 改为卖方所在地 → 风险性需确认，非制式可谈判情形标注「建议法务确认」 |
| 发票税率 | 模板默认 **6%** 增值税专用发票 | 与合同标的实际税率不符 → 真实性/合规性需确认 |

**一致性结论与建议动作**：

| 结论 | 条件 | 建议动作 |
|------|------|---------|
| 一致 | 章节齐全，关键指纹匹配，管理会计要素完整 | 通过（模版维度） |
| 部分偏离 | 章节齐全但个别条款改写（非指纹条款）或填空项未填 | 条件通过——要求说明偏离原因或补全空白 |
| 严重偏离 | 缺少整章、删除买方退货权、主体/金额与审批单明显不一致 | 驳回补材料 / 不通过 |

> **禁止**：表单选「合同模版 = 有」但附件明显为非公司标准结构时，不得仅凭申请人说明放行——须标注「模版声明与正文不一致」。

### 1.4 合同模版 = 无：非模板合同必备审查

**触发**：`contract_template_text` = 无（或表单「合同模版」选「无」）。

非模板合同（对方制式合同、框架协议、服务合同等）**不要求**匹配 `Contract_Templates/` 章节结构，但必须满足以下两类审查。

#### 1.4.1 管理会计必备要素（全部必须有据可查）

以下要素须在合同正文或附件 OCR 中**逐项可提取**；缺失项列入建议卡「需补充/确认」，核心项缺失 → 条件通过或驳回补材料：

| # | 必备要素 | 提取来源 | 缺失处理 |
|---|---------|---------|---------|
| 1 | 买方法人体信息 | 合同首部 / 签署页 | 名称、地址；缺税号时按 SKILL.md 税号查证流程 |
| 2 | 卖方法人体信息 | 合同首部 / 签署页 | 同上 |
| 3 | 双方联系人相关信息 | 首部或通知送达条款 | 联系人、电话、邮箱或送达地址 |
| 4 | 购买产品或服务相关信息 | 标的 / 服务范围条款 | 名称、规格、数量或服务内容描述 |
| 5 | 交货时间、地点 | 交货 / 履行条款 | 期限、地点或履行方式 |
| 6 | 合同开始及结束时间 | 正文或「其他」条款 | 生效日、到期日或项目周期；无明确结束时间须标注「开口合同/至履行完毕」 |
| 7 | 含税金额 | 金额条款 | 与表单 `amount` / 审批单一致 |
| 8 | 税率 | 发票 / 价款条款 | 增值税税率或含税/不含税说明 |
| 9 | 付款时间及方式 | 付款条款 | 预付比例、账期、节点付款等 |
| 10 | 开票信息 | 发票条款 | 买方抬头、税号、开户行账号 |
| 11 | 双方签字盖章 | 签署页 / OCR 视觉 | 双章齐全视为法律有效（见付款标准线下合同规范） |

#### 1.4.2 质量保证与买方退货权（采购类合同重点）

采购类合同（`contract_type_text` = 采购类）且「合同模版 = 无」时，须检查是否包含**与标准模板等效的质量保障**，至少覆盖：

| 审查点 | 最低要求 | 缺失处理 |
|--------|---------|---------|
| 质量标准 | 产品技术指标、验收标准或合格证明要求 | 条件通过——要求补充 |
| 质量异议期限 | 收货后提出异议的时限 | 缺失 → 条件通过 |
| 退换货/退款 | 质量问题下的退货、换货或退款机制 | 缺失 → 条件通过 |
| **买方退货权** | 建议包含以下实质内容（允许表述差异，但权利不得缺失）： | 采购类缺失 → **条件通过**；若完全禁止退货 → 风险性需确认 |

**买方退货权参考标准**（源自 `买卖合同模版.docx` 质量保证第 5 款，非模板合同应包含同等实质）：

> 考虑到买方与其他第三方之间的合作可能受到周期、季节等各种因素影响而造成合同标的物的消耗量随之变化，为灵活应对，买方有权将其未拆封且质量合格的合同标的物退还卖方，本着长期合作的意愿，买方应在新需求产生后，在同等条件下优先从卖方处继续订货。

**审查口径**：
- 有四要素即视为具备等效条款：①消耗量可变背景 ②未拆封且质量合格可退 ③买方退货权 ④优先续订意向
- 对方制式合同完全禁止退货且无替代灵活机制 → 标注「缺少买方退货权灵活条款」，建议动作：**条件通过**（采购类）或**升级法务确认**（金额属「大」级以上）
- 销售类 / 租赁类 / 借款类合同：退货权条款非强制，但须在建议卡标注「非采购类，不适用买方退货权标准」

### 1.5 管理会计要素与表单/API 交叉验证

无论「合同模版」有或无，均须将 OCR 提取内容与审批单字段交叉比对：

| 比对项 | 合同正文 | 审批单/API |
|--------|---------|-----------|
| 买方主体 | 合同首部买方 | 审批 `approval_name` 对应主体 |
| 卖方主体 | 签约主体(对方) | `counterparty_name` |
| 联系人 | 对方负责人/联系方式 | `counterparty_owner` / `counterparty_contact` |
| 金额 | 含税总价 | `amount` |
| 业务目的 | 合同标的描述 | `purpose` |

不一致项列入「关键证据/异常点」，金额不一致优先作为主判定。

### 1.6 建议卡输出补充（模版审查块）

合同建议卡须增加「模版与内容审查」小节（置于「场景归因」之后）：

```

合同模版：{有/无}｜匹配模板：{买卖合同模版.docx / 不适用}
结构一致性：{一致/部分偏离/严重偏离}
管理会计要素：{N/11 项齐全}｜缺失：{列表}

```

## 二、合同类型前置识别（首审第二步）

在进入七项判断之前，必须先识别合同类型。**框架协议走简化审查流程，普通合同走完整七项判断。**

### 2.1 框架协议识别标准

框架协议的核心特征是**约定持续交易框架（单价 + 执行机制），具体每次交易的量/金额留待后续确定**。以下三个条件**同时满足**即为框架协议：

| # | 条件 | 判断方式 |
|---|------|---------|
| ① | **合同目的是建立长期供应/服务关系** | 目的/备注/合同名称中包含"框架""长期""年度""协议支付""月结"，或合同内容明确约定按次/按月/按批下单 |
| ② | **定价方式为约定单价或费率，总量未锁定** | 合同约定单价/费率/计费标准，但总金额取决于未来实际发生量。金额=0 是强烈信号，但不是必要条件（如管理费单价 ¥100/人/月的劳务派遣合同） |
| ③ | **后续有独立执行或结算机制** | 合同约定了每次交易的 PO/运单/结算单/付款审批机制 |

**反例（金额=0 但不是框架协议）**：
- 变更协议/解除协议：不涉及未来持续交易，一次性事项
- 补充协议：依附于既有合同，不独立建立交易框架

**常见框架协议类型**：

| 类型 | 典型特征 | 实例 |
|------|---------|------|
| 运输/物流框架 | 金额=0，约定单价+运单机制 | 中铁快运冷链运输 |
| 检测服务框架 | 金额=0 或 单次单价，按批结算 | 广州丽赛检测服务 |
| 劳务派遣框架 | 金额=管理费单价（如 ¥100/人/月），实际费用按人按月结算 | 智联劳务派遣 |
| 长期供应框架 | 约定单价+最低采购量/预估量，按 PO 执行 | — |

### 2.2 框架协议简化审查流程

识别为框架协议后，**仅审查以下 4 项**，其余 3 项跳过：

| 审查项 | 审查内容 | 来源 |
|--------|---------|------|
| ① 主体资质 | 对方营业执照/税号核验、签署人授权、供应商入库状态 | 原 1.2 真实性 |
| ② 定价标准 | 单价/费率是否与历史一致、定价机制是否清晰 | 原 1.6 价值性 |
| ③ 违约责任框架 | 违约金是否对等、赔偿责任上限是否合理 | 原 1.4 风险性 |
| ④ 争议解决机制 | 管辖地、仲裁/诉讼、是否制式条款不可谈判 | 原 1.4 风险性 |

**明确不审查的 3 项**：

| 跳过项 | 原因 |
|--------|------|
| 必要性（1.5） | 框架协议的必要性由关联项目/采购驱动，不是合同本身 |
| 履约性（1.7） | 履约性取决于每次具体执行，签框架时无法判断 |
| 运营决策类条件 | 保价选择、发货方式、保险购买、单次付款期限等运营决策**不得作为签约前置条件**，由现场负责人在实际执行时确定 |

**禁止行为**：
- 禁止要求特定级别人员（如 GM）对逐次运营决策预先确认
- 禁止将"填写空白字段"作为条件（如保价费率、月结额度、最低月用量等已在合同中明确的字段不属于空白；仅真正的缺失字段需补充）
- 禁止对央企/大型企业制式合同条款提出修改建议（争议解决地、滞纳金比例等），标注"制式条款，不可谈判"即可

**框架协议建议卡模板**（精简版）：

```
## 合同审批建议卡（框架协议）：{审批单号}

### 建议动作：{通过/条件通过/驳回补材料}
### 风险等级：{低/中/中高/高}
### 建议信心：{高/中高/中/中低/低}

### 框架协议判定
{触发条件①-③的简述}

### 四项审查
| 审查项 | 结论 | 说明 |
|--------|------|------|
| 主体资质 | 通过/条件 | ... |
| 定价标准 | 通过/条件 | ... |
| 违约责任框架 | 通过/条件 | ... |
| 争议解决 | 通过/条件 | ... |

### 条件明细（如有）
| # | 条件内容 | 责任人 | 截止时间 | 逾期处理 |
|-|-|-|-|-|
```

## 三、合同审批七项判断标准（普通合同）

> 进入本章前须先完成 **§一 合同模版与内容审查** 和 **§二 合同类型前置识别**。

### 3.1 场景归因 — 合同从哪个真实业务场景来？

**定义**：在进入条款审查之前，必须先完成原始场景追踪，确定合同为哪个真实业务场景而存在。

**五级追踪体系**：

| 追踪层级 | 适用对象 | 归因路径 |
|-|-|-|
| 一级：主营业务 | CGT 主业务合同 | 合同 → 管线/研发/临床项目 → 批次/物料/服务/检测 → IND/注册节点 |
| 二级：业务交易 | 销售、采购类合同 | 合同 → SO/PO/采购申请 → 库存/交付/生产计划 |
| 三级：组织对象 | 支持运营类合同 | 合同 → 部门/成本中心 → 预算 → 组织目标 |
| 四级：一般运营 | 常规行政、基础服务 | 预算内、采购周期、历史价格基准、常规消耗 |
| 五级：无法追踪 | 无法关联任何对象 | **视为高风险，建议驳回补材料** |

---

### 3.2 真实性 — 交易背景和合同信息真实吗？

**必查项**：
- [ ] **§一 模版与内容审查**已完成（管理会计要素、金额与审批单交叉验证）
- [ ] 签约主体名称、工商登记信息
- [ ] 项目与公司层面费用字段（`has_affiliated_project_text`、`project_code`、`is_rd_expense_text`、`is_daily_expense_text`）一致性
- [ ] 关联采购申请（`related_buy_instance_codes`）：先查 `/data/buy-v2/`，404 时回退 `/data/buy/`（旧流程 `F753B844-865B-4B3D-B44A-544F3178F8F1`）
- [ ] 对方主体资质——满足以下任一即通过，**不再单独要求营业执照**：
  1. 供应商在合格供应商库内（见供应商主表，「是否在合格供应商库」为「是」）
  2. 关联的采购申请已批准且供应商类型为「合格供应商」
  3. 合同/发票/收款方信息中已包含税号（按税号查证流程核验）
  4. 历史合作次数 ≥ 3 次（从供应商主表或历史付款记录确认）
- [ ] 签署人授权文件——满足以下任一即免于要求：
  1. 对方为独立法人（非分公司/分支机构），合同已盖公章或合同专用章
  2. 对方为分公司但供应商在合格库内且历史合作 ≥ 3 次（长期合作关系中签约授权已被实际履行验证）
  3. 对方为分公司但关联采购申请已批准
  4. 仅对方为分公司且首次合作或合作 ≤ 2 次时，才需确认总公司签约授权
- [ ] 交易背景说明（申请人填写）
- [ ] 报价单/技术协议与合同金额、标的匹配

### 3.2.1 项目与公司层面费用字段规范

| 情形 | 判定 | 合规处理 |
|-|-|-|
| `has_affiliated_project_text` = 是 | 有所属项目 | `project_code` 必须有具体项目编号 |
| `is_rd_expense_text` = 是 | 公司层面研发费用 | 可不关联项目，建议卡标注费用性质 |
| `is_daily_expense_text` = 是 | 公司层面日常费用 | 可不关联项目，建议卡标注费用性质 |
| 人数据相关合同 | 无论上述字段 | **必须**关联具体项目编号 |

### 3.3 合规性 — 能不能按规则签？

**必查项**：
- [ ] 法律红线检查（强制性规定 / 公序良俗 / 国家安全 / 公共利益 / 公平竞争 / 虚假交易 / 关联交易）
- [ ] **合同模版审查**（§一）：`contract_template_text` = 有 → 比对 `Contract_Templates/`；= 无 → 管理会计 11 项 + 买方退货权（采购类）
- [ ] 授权审批（飞书审批流已配置）
- [ ] 行业监管要求（数据合规/出口管制/反商业贿赂）
- [ ] GMP/QA 文档要求

**红线触发规则**：

| 红线类别 | 触发条件 | 建议动作 |
|-|-|-|
| 强制性规定 | 违反法律、行政法规强制性规定 | **不通过** / 法务专项审查 |
| 公序良俗 | 违背公共秩序或善良风俗 | **不通过** / 法务专项审查 |
| 国家安全 | 影响政治、经济、军事、数据安全 | **升级合规审查** |
| 虚假交易 | 恶意串通、利益输送、虚假合同 | **不通过** |
| 关联交易 | 未披露关联关系或利益冲突 | **补材料** / 合规审查 |

---

### 3.4 风险性 — 权利义务和条款风险是否可控？

**重点审查项**：
- [ ] 技术协议完整内容
- [ ] 质量协议/验收标准
- [ ] IP 条款/保密条款
- [ ] 违约责任条款（是否对等、是否充分）
- [ ] 争议解决条款
- [ ] 交付与付款的匹配关系
- [ ] 赔偿责任上限

---

### 3.5 必要性 — 现在有没有必要签？

与付款必要性同源，额外增加：
- [ ] 不签是否影响关键项目节点（IND/临床/注册）
- [ ] 不签是否形成库存或供应风险
- [ ] 不签是否影响客户关系或组织目标

---

### 3.6 价值性 — 签了是否值得？

与付款价值性同源，额外增加：
- [ ] 合同对收入、供应保障、管线进展的直接贡献
- [ ] 价格与历史同类合同偏差
- [ ] 替代供应商或替代方案的可用性

---

### 2.7 履约性 — 企业能不能做到？

**定义**：判断企业当前是否有资源、产能、时间履行合同义务。

**必查项**：
- [ ] 项目资源排期 / 关键里程碑
- [ ] QA 审核周期
- [ ] 产能/交付能力状态
- [ ] 预算是否已预留

## 五、合同扩展数据抽取与推送

> 审查结束后由 SKILL.md 步骤 9 调用 `POST /hetang-payment-apply/push-contract-ext-data`。
> 每次合同 AI 审查（含复查模式）均执行；POST 失败不阻断审查。

### 5.1 字段定义与抽取来源

| 字段 | 必填 | 抽取来源 | 格式 / 说明 |
|------|------|---------|------------|
| `serial_number` | **是** | `/data/contract/` → `serial_number` | 审批单号；缺失则**跳过推送** |
| `approval_code` | 否 | 同上 → `approval_code` | 审批模板编码 |
| `instance_code` | 否 | 同上 → `instance_code` | 审批实例编码 |
| `approval_name` | 否 | 同上 → `approval_name` | 审批模板名称 |
| `contract_summary` | 否 | AI 综合审查上下文生成 | 一句话摘要，如「与广州粤佳气体有限公司签订液氮为期3年的采购合同」 |
| `contract_start_date` | 否 | 合同 OCR / 正文生效条款 | `YYYY-MM-DD` |
| `contract_end_date` | 否 | 合同 OCR / 正文到期条款 | `YYYY-MM-DD`；开口合同无明确到期日则不传 |
| `is_framework_contract` | 否 | §2.1 框架协议三条件判定 | `是` / `否` |
| `tax_rate` | 否 | OCR 发票/价款条款（§1.4.1 第 8 项） | 如 `13%`、`6%` |
| `payment_nodes` | 否 | OCR 付款条款 / `remark` | **仅** `contract_type_text` = 采购类；如「预付30%，验收70%」 |

### 5.2 抽取优先级

1. hetang 合同 API 结构化字段（步骤 2）
2. 附件 OCR（`attachments_ocr_text`）
3. 关联采购（`related_buy_instance_codes` → buy-v2 / buy）
4. 审批评论中人工确认声明（风控/法务/财务，见 SKILL.md 确认人员清单）
5. 仍无法确定 → **不传该 key**

OCR 与人工确认冲突时，以人工确认为准（SKILL.md 共享规则）。

### 5.3 `contract_summary` 生成要点

综合以下信息生成一句完整中文摘要（审查过程中即可形成，供步骤 9 直接使用）：

- 对方单位：`counterparty_name`
- 标的/目的：`topic`、`purpose`、OCR 标的描述
- 合同类型/期限：`contract_type_text`、起止日期或「长期/框架」等
- 示例：「与广州粤佳气体有限公司签订液氮为期3年的采购合同」

### 5.4 `is_framework_contract` 判定

复用 §2.1 框架协议识别标准：三条件**同时满足** → `是`，否则 → `否`。

### 5.5 `payment_nodes` 范围

| `contract_type_text` | 是否传 `payment_nodes` |
|---------------------|----------------------|
| 采购类 | 能抽取到付款节点时传 |
| 销售类 / 租赁类 / 借款类 / 其他类 | **不传此 key** |

### 5.6 Payload 组装规则

- **必含**：`serial_number`（有值）
- **按需含**：其余字段仅在有确定值时加入 JSON
- **禁止**：对抽取不到的字段传 key（包括 `null`、`""`、占位符）
- **禁止**：非采购类传 `payment_nodes`
