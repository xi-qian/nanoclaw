## 零、合同类型前置识别（首审第一步）

在进入七项判断之前，必须先识别合同类型。**框架协议走简化审查流程，普通合同走完整七项判断。**

### 0.1 框架协议识别标准

框架协议的核心特征是**约定持续交易框架（单价 + 执行机制），具体每次交易的量/金额留待后续确定**。以下三个条件**同时满足**即为框架协议：

| # | 条件 | 判断方式 |
|---|------|---------|
| ① | **合同目的是建立长期供应/服务关系** | purpose/remark/合同标题中包含"框架""长期""年度""协议支付""月结"，或合同内容明确约定按次/按月/按批下单 |
| ② | **定价方式为约定单价或费率，总量未锁定** | 合同约定单价/费率/计费标准，但总金额取决于未来实际发生量。金额=0 是强烈信号，但不是必要条件（如管理费单价 ¥100/人/月的劳务派遣合同） |
| ③ | **后续有独立执行或结算机制** | 合同约定了每次交易的 PO/运单/结算单/付款审批机制 |

**反例（金额=0 但不是框架协议）**：
- 变更协议/解除协议：不涉及未来持续交易，一次性事项
- 补充协议：依附于既有合同，不独立建立交易框架

**常见框架协议类型**：

| 类型 | 典型特征 | 实例 |
|------|---------|------|
| 运输/物流框架 | 金额=0，约定单价+运单机制 | 中铁快运冷链运输 |
| 检测服务框架 | 金额=0 或 单次单价，按批结算 | 广州丽赛检测服务 |
| 劳务派遣框架 | 金额=管理费单价（如 ¥100/人/月），实际费用按人按月结算 | 智联劳务派遣 |
| 长期供应框架 | 约定单价+最低采购量/预估量，按 PO 执行 | — |

### 0.2 框架协议简化审查流程

识别为框架协议后，**仅审查以下 4 项**，其余 3 项跳过：

| 审查项 | 审查内容 | 来源 |
|--------|---------|------|
| ① 主体资质 | 对方营业执照/税号核验、签署人授权、供应商入库状态 | 原 1.2 真实性 |
| ② 定价标准 | 单价/费率是否与历史一致、定价机制是否清晰 | 原 1.6 价值性 |
| ③ 违约责任框架 | 违约金是否对等、赔偿责任上限是否合理 | 原 1.4 风险性 |
| ④ 争议解决机制 | 管辖地、仲裁/诉讼、是否制式条款不可谈判 | 原 1.4 风险性 |

**明确不审查的 3 项**：

| 跳过项 | 原因 |
|--------|------|
| 必要性（1.5） | 框架协议的必要性由关联项目/采购驱动，不是合同本身 |
| 履约性（1.7） | 履约性取决于每次具体执行，签框架时无法判断 |
| 运营决策类条件 | 保价选择、发货方式、保险购买、单次付款期限等运营决策**不得作为签约前置条件**，由现场负责人在实际执行时确定 |

**禁止行为**：
- 禁止要求特定级别人员（如 GM）对逐次运营决策预先确认
- 禁止将"填写空白字段"作为条件（如保价费率、月结额度、最低月用量等已在合同中明确的字段不属于空白；仅真正的缺失字段需补充）
- 禁止对央企/大型企业制式合同条款提出修改建议（争议解决地、滞纳金比例等），标注"制式条款，不可谈判"即可

**框架协议建议卡模板**（精简版）：

```
## 合同审批建议卡（框架协议）：{审批单号}

### 建议动作：{通过/条件通过/驳回补材料}
### 风险等级：{低/中/中高/高}
### 建议信心：{高/中高/中/中低/低}

### 框架协议判定
{触发条件①-③的简述}

### 四项审查
| 审查项 | 结论 | 说明 |
|--------|------|------|
| 主体资质 | 通过/条件 | ... |
| 定价标准 | 通过/条件 | ... |
| 违约责任框架 | 通过/条件 | ... |
| 争议解决 | 通过/条件 | ... |

### 条件明细（如有）
| # | 条件内容 | 责任人 | 截止时间 | 逾期处理 |
|-|-|-|-|-|
```

## 一、合同审批七项判断标准（普通合同）

### 1.1 场景归因 — 合同从哪个真实业务场景来？

**定义**：在进入条款审查之前，必须先完成原始场景追踪，确定合同为哪个真实业务场景而存在。

**五级追踪体系**：

| 追踪层级 | 适用对象 | 归因路径 |
|-|-|-|
| 一级：主营业务 | CGT 主业务合同 | 合同 → 管线/研发/临床项目 → 批次/物料/服务/检测 → IND/注册节点 |
| 二级：业务交易 | 销售、采购类合同 | 合同 → SO/PO/采购申请 → 库存/交付/生产计划 |
| 三级：组织对象 | 支持运营类合同 | 合同 → 部门/成本中心 → 预算 → 组织目标 |
| 四级：一般运营 | 常规行政、基础服务 | 预算内、采购周期、历史价格基准、常规消耗 |
| 五级：无法追踪 | 无法关联任何对象 | **视为高风险，建议驳回补材料** |

---

### 1.2 真实性 — 交易背景和合同信息真实吗？

**必查项**：
- [ ] 签约主体名称、工商登记信息
- [ ] 对方主体资质——满足以下任一即通过，**不再单独要求营业执照**：
  1. 供应商在合格供应商库内（见供应商主表，「是否在合格供应商库」为「是」）
  2. 关联的采购申请已批准且供应商类型为「合格供应商」
  3. 合同/发票/收款方信息中已包含税号（按税号查证流程核验）
  4. 历史合作次数 ≥ 3 次（从供应商主表或历史付款记录确认）
- [ ] 签署人授权文件——满足以下任一即免于要求：
  1. 对方为独立法人（非分公司/分支机构），合同已盖公章或合同专用章
  2. 对方为分公司但供应商在合格库内且历史合作 ≥ 3 次（长期合作关系中签约授权已被实际履行验证）
  3. 对方为分公司但关联采购申请已批准
  4. 仅对方为分公司且首次合作或合作 ≤ 2 次时，才需确认总公司签约授权
- [ ] 交易背景说明（申请人填写）
- [ ] 报价单/技术协议与合同金额、标的匹配

---

### 1.3 合规性 — 能不能按规则签？

**必查项**：
- [ ] 法律红线检查（强制性规定 / 公序良俗 / 国家安全 / 公共利益 / 公平竞争 / 虚假交易 / 关联交易）
- [ ] 标准合同模板对照（法务提供模板库 → 知识库 RAG 检索）
- [ ] 授权审批（飞书审批流已配置）
- [ ] 行业监管要求（数据合规/出口管制/反商业贿赂）
- [ ] GMP/QA 文档要求

**红线触发规则**：

| 红线类别 | 触发条件 | 建议动作 |
|-|-|-|
| 强制性规定 | 违反法律、行政法规强制性规定 | **不通过** / 法务专项审查 |
| 公序良俗 | 违背公共秩序或善良风俗 | **不通过** / 法务专项审查 |
| 国家安全 | 影响政治、经济、军事、数据安全 | **升级合规审查** |
| 虚假交易 | 恶意串通、利益输送、虚假合同 | **不通过** |
| 关联交易 | 未披露关联关系或利益冲突 | **补材料** / 合规审查 |

---

### 1.4 风险性 — 权利义务和条款风险是否可控？

**重点审查项**：
- [ ] 技术协议完整内容
- [ ] 质量协议/验收标准
- [ ] IP 条款/保密条款
- [ ] 违约责任条款（是否对等、是否充分）
- [ ] 争议解决条款
- [ ] 交付与付款的匹配关系
- [ ] 赔偿责任上限

---

### 1.5 必要性 — 现在有没有必要签？

与付款必要性同源，额外增加：
- [ ] 不签是否影响关键项目节点（IND/临床/注册）
- [ ] 不签是否形成库存或供应风险
- [ ] 不签是否影响客户关系或组织目标

---

### 1.6 价值性 — 签了是否值得？

与付款价值性同源，额外增加：
- [ ] 合同对收入、供应保障、管线进展的直接贡献
- [ ] 价格与历史同类合同偏差
- [ ] 替代供应商或替代方案的可用性

---

### 1.7 履约性 — 企业能不能做到？

**定义**：判断企业当前是否有资源、产能、时间履行合同义务。

**必查项**：
- [ ] 项目资源排期 / 关键里程碑
- [ ] QA 审核周期
- [ ] 产能/交付能力状态
- [ ] 预算是否已预留
